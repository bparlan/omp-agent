#### Objective

Transform the CLI argument parsing and orchestration logic from the existing monolithic wrapper into a focused `cli.py` module at the project root. This module provides the command-line interface contract, orchestrates validation discovery and execution across single-skill and batch modes, and coordinates report generation — while maintaining backward compatibility with the existing `python3 healthcheck.py [skill_name]` and `python3 healthcheck.py --all` invocation patterns.

##### Milestone Complexity & Multi-Spec Plan

Milestone M8 decomposes into exactly 5 sequential specifications:

- **M8S1** (completed): Core validation module (`core/validation.py`)
- **M8S2** (completed): Discovery module (`discovery.py`)
- **M8S3** (completed): Reporting module (`reporting.py`)
- **M8S4** (this spec): CLI module (`cli.py`) — argument parsing and orchestration
- **M8S5**: Main entry point (`main.py`) with minimal glue logic

This spec addresses only HCS4 (CLI). It MUST NOT redefine validation contracts from M8S1, discovery contracts from M8S2, nor reporting contracts from M8S3.

#### Functional Requirements

##### `FR-CLI_MODULE_EXPORTS`

- **Type**: Structured Schema Contract (Python module interface)
- **Interface Contract**: Module `cli.py` exports five functions: `parse_arguments() -> argparse.Namespace`, `validate_single_skill(skill_name: str) -> Optional[Dict[str, Any]]`, `process_all_skills() -> List[Dict[str, Any]]`, `run_health_check(skill_name: Optional[str] = None, all_flag: bool = False) -> List[Dict[str, Any]]`, `print_help() -> None`, and `generate_all_reports(results: List[Dict[str, Any]]) -> None`.
- **Expected Behavior**: Functions are importable without importing `main.py` or any CLI-specific orchestration layer. Each function performs a single, well-defined operation. Side effects are limited to stdout/stderr output and delegation to other modules.
- **Observable Boundary**: Module import succeeds (`import cli`); `dir(cli)` contains all six exported symbols; calling `parse_arguments()` with `sys.argv` overridden returns a valid `argparse.Namespace`; calling `print_help()` writes to stdout; calling `validate_single_skill("nonexistent")` returns `None` and writes to stderr.

##### `FR-CLI_ARGUMENT_PARSING`

- **Type**: CLI Executable Contract
- **Interface Contract**: `cli.parse_arguments()` uses `argparse.ArgumentParser` with:
  - Positional argument `skill_name` (optional, `nargs='?'`) — specific skill name to check.
  - Flag `--all` (`action='store_true')` — process all skills in 3 batches.
  - Flag `--help` (`action='store_true')` — show help message.
- **Expected Behavior**: When invoked as `python3 -c "import sys; sys.argv=['healthcheck.py']; from cli import parse_arguments; print(parse_arguments())"` the namespace has `skill_name=None`, `all_flag=False`, `help_flag=False`. When invoked as `python3 -c "import sys; sys.argv=['healthcheck.py','my_skill']; from cli import parse_arguments; print(vars(parse_arguments()))"` the namespace has `skill_name='my_skill'`, `all_flag=False`. When invoked as `python3 -c "import sys; sys.argv=['healthcheck.py','--all']; from cli import parse_arguments; print(vars(parse_arguments()))"` the namespace has `skill_name=None`, `all_flag=True`.
- **Observable Boundary**: Programmatic invocation with overridden `sys.argv` produces expected `argparse.Namespace` attributes; exit code 0 for `--help` invocation.

##### `FR-CLI_SINGLE_SKILL_MODE`

- **Type**: Structured Schema Contract
- **Interface Contract**: `cli.validate_single_skill(skill_name: str) -> Optional[Dict[str, Any]]` accepts a skill name string, locates the corresponding `SKILL.md` file via `discovery.discover_skills()`, reads file content, validates via `SkillValidator().validate(content)`, prints status line to stdout, and returns the result dictionary or `None` if skill not found.
- **Expected Behavior**: For a valid skill name, returns a dict with keys `score` (float), `status` (str), `fields_checked` (list), `field_results` (dict), `errors` (list), `stable_suffix_detected` (bool). For a nonexistent skill name, writes `"Skill '{name}' not found"` to stderr and returns `None`.
- **Observable Boundary**: Return value matches `core.validation.SkillValidator.validate()` output schema; stderr contains error message for missing skill; stdout contains status line for found skill.

##### `FR-CLI_BATCH_PROCESSING`

- **Type**: Structured Schema Contract
- **Interface Contract**: `cli.process_all_skills() -> List[Dict[str, Any]]` discovers all skills via `discovery.discover_skills()`, partitions them into 3 batches (first 3 → Batch 1: Core, next 3 → Batch 2: Extensions, remaining → Batch 3: Edge Cases), validates each skill in batch order, prints batch headers and per-skill status lines to stdout, prints batch summary counts, and returns concatenated list of all result dictionaries.
- **Expected Behavior**: For N skills, Batch 1 processes `skills[0:3]`, Batch 2 processes `skills[3:6]`, Batch 3 processes `skills[6:]`. Each batch prints `"=== BATCH X: <LABEL> ==="` header, per-skill `"Checking <name>... <status> (score: X.XX)"` lines, and a summary block with counts per batch and total. Return list preserves batch ordering.
- **Observable Boundary**: Returned list length equals number of discovered skills; batch headers appear in stdout in order 1, 2, 3; summary counts match list lengths; ordering matches input discovery order.

##### `FR-CLI_DEFAULT_MODE`

- **Type**: Structured Schema Contract
- **Interface Contract**: `cli.run_health_check(skill_name: Optional[str] = None, all_flag: bool = False) -> List[Dict[str, Any]]` dispatches based on arguments: if `skill_name` is set, calls `validate_single_skill`; if `all_flag` is True, calls `process_all_skills`; otherwise discovers all skills, validates each without batch structure, and returns results list.
- **Expected Behavior**: Default mode (no args) prints `"Found N skills to check"` header, validates each skill in discovery order, prints per-skill status lines, returns list of results.
- **Observable Boundary**: Returned list contains one result dict per discovered skill in default mode; stdout contains discovery count header; no batch headers in default mode.

##### `FR-CLI_REPORT_GENERATION`

- **Type**: Structured Schema Contract
- **Interface Contract**: `cli.generate_all_reports(results: List[Dict[str, Any]]) -> None` orchestrates report generation by calling `reporting.generate_badges(results)`, `reporting.generate_health_report(results)`, and `reporting.generate_processed_skills(results)`, then prints a summary block to stdout with total/healthy/needs_review/error counts and percentages, plus a stable-skills section listing skills with `status == 'healthy'` and `has_stable_suffix == True`.
- **Expected Behavior**: Summary counts are integers; percentages formatted as `"X.X%"`; stable skills listed alphabetically; report files created in skills directory via `discovery.get_skills_directory()`.
- **Observable Boundary**: Files `health_badges.md`, `health_check_report.json`, and `processed_skills.json` exist in skills directory after invocation; stdout contains summary section with correct counts matching input results.

##### `FR-CLI_HELP_DISPLAY`

- **Type**: Structured Schema Contract
- **Interface Contract**: `cli.print_help() -> None` prints a multi-line help text string to stdout containing usage instructions, validation criteria, and report descriptions.
- **Expected Behavior**: Help text contains the strings `"healthcheck.py [skill_name]"`, `"healthcheck.py --all"`, `"healthcheck.py --help"`, `"Required fields: name, version, description, tools, userInvocable"`, `"-stable suffix"`, and report file names.
- **Observable Boundary**: stdout contains all required substrings; no exceptions raised; return value is `None`.

##### `FR-CLI_ERROR_HANDLING`

- **Type**: Structured Schema Contract
- **Interface Contract**: When `cli.run_health_check()` or `cli.process_all_skills()` encounters an exception during validation, the error is caught, a message is printed to stderr, and an empty list is returned. `KeyboardInterrupt` prints `"\nOperation interrupted by user."` to stderr.
- **Expected Behavior**: Exceptions during validation do not crash the process; stderr contains error description; returned list may be empty but is always a list.
- **Observable Boundary**: Process exit code is 0 for successful runs, 1 for failures (no results or error); stderr contains error message; no unhandled exceptions propagate.

##### `FR-CLI_EXECUTABLE_INTEGRATION`

- **Type**: CLI Executable Contract
- **Interface Contract**: When `skills/healthcheck/healthcheck.py` is executed via `python3 skills/healthcheck/healthcheck.py`, it delegates to `main.main()` which calls `cli.run_health_check()` and `cli.generate_all_reports()`. The `skills/healthcheck/index.js` wrapper executes `python3 <healthcheck.py path>` and captures stdout/stderr.
- **Expected Behavior**: `python3 skills/healthcheck/healthcheck.py` exits 0 on success, 1 on failure; stdout contains validation status lines and report summary; stderr contains errors.
- **Observable Boundary**: Exit code matches success/failure; stdout and stderr streams contain expected content; process completes within 30 seconds (per `index.js` timeout).

#### Non-Functional Requirements

##### `NFR-CLI_MODULAR_INDEPENDENCE`

- **Constraint**: `cli.py` MUST be importable and testable without importing `main.py`, `index.js`, or any orchestration layer. The only allowed cross-module dependencies are `core.validation`, `discovery`, and `reporting`.
- **Verification**: Unit tests in `tests/M8/S4/` import only `cli` and standard library modules; no import of `main`, `index.js`, or orchestration layers.

##### `NFR-CLI_TYPE_HINTS`

- **Constraint**: All public functions annotated with Python type hints.
- **Verification**: Static inspection via `typing.get_type_hints` confirms annotations on all public functions in `cli.py`.

##### `NFR-CLI_NO_MUTABLE_GLOBALS`

- **Constraint**: No module-level mutable global state in `cli.py`.
- **Verification**: AST inspection confirms zero module-level assignments of mutable types (list, dict, set).

##### `NFR-CLI_BACKWARD_COMPATIBILITY`

- **Constraint**: CLI interface must be functionally equivalent to the existing `skills/healthcheck/cli.py` interface: same argument names (`skill_name`, `--all`, `--help`), same stdout output format, same exit codes.
- **Verification**: Integration tests compare stdout output format and exit codes against reference patterns from `skills/healthcheck/cli.py`.

##### `NFR-CLI_FILE_SCOPE`

- **Constraint**: `cli.py` imports only from `core.validation`, `discovery`, `reporting`, and standard library (`argparse`, `sys`, `pathlib`, `typing`). No imports from `main`, `index.js`, `healthcheck.py`, or any other orchestration module.
- **Verification**: AST inspection of import statements in `cli.py` and its test files confirms allowed modules only.
