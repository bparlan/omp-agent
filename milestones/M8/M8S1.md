#### Objective

Transform the validation logic from the monolithic `healthcheck.py` (237 lines) into a pure, testable `core/validation.py` module with `Validator` base classes, preserving all 5 required field checks (`name`, `version`, `description`, `tools`, `userInvocable`), scoring (0.0-1.0 scale, 0.8 threshold), `-stable` suffix detection, and zero filesystem side effects.

##### Milestone Complexity & Multi-Spec Plan

Milestone M8 decomposes into exactly 5 sequential specifications:

- **M8S1** (this spec): Core validation module (`core/validation.py`)
- **M8S2**: Discovery module (`discovery.py`)
- **M8S3**: Reporting module (`reporting.py`)
- **M8S4**: CLI module (`cli.py`)
- **M8S5**: Main entry point (`main.py`)

This spec addresses only HCS1. Other specs SHALL NOT redefine HCS1 contracts.

#### Functional Requirements

##### `FR-VALIDATOR_BASE_CLASS`

- **Type**: Structured Schema Contract (Python module interface)
- **Interface Contract**: Module `core/validation.py` exports abstract base class `Validator` (or `ValidatorBase`) with pure method `validate(content: str) -> Dict[str, Any]`.
- **Expected Behavior**: Subclasses inherit from base; method takes SKILL.md content string, returns structured result dict. No filesystem I/O permitted inside `validate()`.
- **Observable Boundary**: Module import succeeds (`import core.validation`); `Validator` is abstract; `validate()` accepts `str`, returns `dict`.

##### `FR-FIELD_CHECK_RULES`

- **Type**: Structured Schema Contract
- **Interface Contract**: Validation checks exactly the 5 required fields: `name`, `version`, `description`, `tools`, `userInvocable`.
- **Expected Behavior**: Each missing/incomplete field reduces score; complete fields yield maximum per-field contribution. Score computed as float in [0.0, 1.0].
- **Observable Boundary**: Input `str` produces output `dict` with keys `fields_checked` (list of 5 strings) and `field_results` (dict of bool/string results).

##### `FR-SCORING_ALGORITHM`

- **Type**: Structured Schema Contract
- **Interface Contract**: Scoring preserved: float range [0.0, 1.0]; threshold 0.8 determines pass/fail status.
- **Expected Behavior**: Score computed deterministically from field results; no randomness; no external state dependency.
- **Observable Boundary**: `validate()` output `dict` contains `score: float` in [0.0, 1.0] and `status: str` (`"PASS"` if score >= 0.8 else `"FAIL"`).

##### `FR-STABLE_SUFFIX_DETECTION`

- **Type**: Filesystem State Contract / Structured Schema Contract
- **Interface Contract**: Detection of `-stable` suffix in skill name/version preserved.
- **Expected Behavior**: Validation logic checks for `-stable` suffix without filesystem access; operates purely on input content string.
- **Observable Boundary**: Validation result `dict` contains `stable_suffix_detected: bool` (or equivalent structured flag) derived solely from input `str`.

##### `FR-PURE_VALIDATION_NO_IO`

- **Type**: Filesystem State Contract / Structured Schema Contract
- **Interface Contract**: `core/validation.py` contains zero file-read/write operations; zero environment mutations.
- **Expected Behavior**: Module import and execution produces no filesystem changes; no `open()`, no `os.path`, no `pathlib` I/O calls within module functions.
- **Observable Boundary**: Static analysis confirms absence of I/O calls in `core/validation.py`; module import has zero filesystem side effects.

##### `FR-VALIDATION_ERROR_HANDLING`

- **Type**: Structured Schema Contract
- **Interface Contract**: Malformed or empty SKILL.md content handled gracefully; returns structured error result rather than raising unhandled exception.
- **Expected Behavior**: Empty string or missing fields yields score 0.0, status `FAIL`, with explicit error indicators in result dict.
- **Observable Boundary**: Input `""` returns `dict` with `score: 0.0`, `status: "FAIL"`, `errors: list` (non-empty) — observable without exception propagation.

#### Non-Functional Requirements

##### `NFR-MODULAR_TESTABILITY`

- **Constraint**: Each validation function/class independently importable and unit-testable without importing `cli.py`, `discovery.py`, or `main.py`.
- **Verification**: Import `core.validation.Validator` in isolation succeeds; unit tests in `tests/` import only from `core.validation`.

##### `NFR-TYPE_HINTS`

- **Constraint**: All public functions/classes annotated with Python type hints (`str`, `Dict[str, Any]`, `float`).
- **Verification**: Static inspection confirms annotations present on `validate()` and constructor methods.

##### `NFR-BACKWARD_COMPATIBILITY`

- **Constraint**: Validation results structurally equivalent to pre-refactor `healthcheck.py` behavior (same field checks, same score scale, same threshold).
- **Verification**: Unit tests compare output dict structure against reference outputs derived from existing `healthcheck_modular_spec.md` criteria.

- `core/validation.py` receives: raw `str` (SKILL.md file content) from caller.
- `core/validation.py` returns: structured `Dict[str, Any]` with minimum observable keys: `score` (float), `status` (str), `fields_checked` (list of 5 str), `field_results` (dict), `errors` (list of str), and `stable_suffix_detected` (bool or structured equivalent).
