## Verification Items

### V-001: Main Orchestration Contract

**Source Requirement ID:** FR-MAIN_ORCHESTRATION

**Verification Method:** SCRIPT_EXECUTION

**Target:** Root-level `main.py`

**Preconditions:**
- `cli.py` exists at project root and exports `parse_arguments()`, `run_health_check()`, `print_help()`, `generate_all_reports()`
- `core/validation.py` exists and exports `SkillValidator`
- `discovery.py` exists and exports `discover_skills`, `get_skills_directory`
- `reporting.py` exists and exports report generation functions

**Input / Fixture:**
- Execute: `python3 main.py --help`
- Execute: `python3 main.py` with no arguments in project root
- Execute: `python3 main.py <skill_name>` where `<skill_name>` is a valid discovered skill
- Execute: `python3 main.py --all`

**Expected Evidence:**
- `main.py` exists at project root
- `main.py` imports from `cli`, `discovery`, `reporting`, `core.validation`
- `main.py` defines `main()` function and `if __name__ == "__main__"` guard
- No errors during import of `main.py`
- CLI invocation routes through root `main.py` and uses root `cli.py` functions

**Failure Condition:**
- `main.py` does not exist at project root
- Import of `main.py` raises exceptions
- Invocation uses wrapper-local imports instead of root-level modules

**Initial Failure Expectation:**
- Exit code 127 or 1 if `main.py` does not exist at root

**Post-Implementation Success Expectation:**
- `main.py` exists at project root
- All root invocations succeed with exit code 0 for valid operations
- Output generated by root module orchestration

### V-002: Backward Compatibility Contract

**Source Requirement ID:** FR-MAIN_BACKWARD_COMPAT

**Verification Method:** SCRIPT_EXECUTION

**Target:** `python3 main.py [skill_name]` and `python3 main.py --all` invocation patterns

**Preconditions:**
- At least one valid skill exists under `skills/`
- `main.py` exists at project root

**Input / Fixture:**
- Execute: `python3 main.py` with no arguments
- Execute: `python3 main.py --help`
- Execute: `python3 main.py --all` in a project with discoverable skills
- Execute: `python3 main.py <valid_skill_name>` from project root

**Expected Evidence:**
- No-arg invocation runs default healthcheck mode without argparse errors
- `--help` prints usage text and exits with code 0
- `--all` discovers and processes all skills via `discover_skills()`
- `<skill_name>` invocation validates only the named skill
- Invocation patterns match `python3 healthcheck.py` historical behavior

**Failure Condition:**
- No-arg invocation fails with usage/argument errors
- `--all` does not process discovered skills
- Named skill invocation does not delegate to single-skill mode

**Initial Failure Expectation:**
- Exit code 127 if `main.py` missing; exit code 1 for argument parsing failures before implementation

**Post-Implementation Success Expectation:**
- All invocation patterns complete successfully
- Results match expectations from `cli.py` contract

### V-003: Error Handling Contract

**Source Requirement ID:** FR-MAIN_ERROR_HANDLING

**Verification Method:** UNIT_TEST

**Target:** Exception handling paths in `main.py`

**Preconditions:**
- `main.py` exists at project root
- `cli.py` provides error-raising entry points

**Input / Fixture:**
- Call `main()` when `discover_skills()` raises `DiscoveryError`
- Call `main()` when `SkillValidator.validate()` raises `ValidationError`
- Call `main()` when `generate_all_reports()` raises `ReportingError`
- Call `main()` with `KeyboardInterrupt`

**Expected Evidence:**
- Exceptions are caught and printed to stderr or otherwise surfaced
- Function returns integer exit status (0 for success, non-zero for failure)
- No unhandled exception tracebacks propagate to caller in normal operation
- `KeyboardInterrupt` handled gracefully without traceback

**Failure Condition:**
- Unhandled exception propagates out of `main()`
- `KeyboardInterrupt` produces traceback or hangs
- Exit status does not reflect success/failure

**Initial Failure Expectation:**
- Missing `main.py` or missing handlers causes exit code 127 or 1

**Post-Implementation Success Expectation:**
- All tested error paths return deterministic non-zero exit status
- stderr contains human-readable error context

### V-004: Modular Independence Contract

**Source Requirement ID:** FR-MAIN_MODULAR_INDEPENDENCE

**Verification Method:** UNIT_TEST

**Target:** Import audit of `main.py`

**Preconditions:**
- `main.py` exists at project root

**Input / Fixture:**
- Inspect `main.py` AST/tokens or attempt import in isolated environment
- Verify imports include only: `cli`, `discovery`, `reporting`, `core.validation`, stdlib modules
- Verify no imports from `skills.healthcheck.*`, local wrapper modules, or unrelated packages

**Expected Evidence:**
- All imports resolve to root-level modules or Python stdlib
- No prohibited wrapper-local imports exist
- Import succeeds without side effects

**Failure Condition:**
- `main.py` imports from `skills.healthcheck.healthcheck` or similar wrapper-local paths
- Import resolves to non-root duplicated modules

**Initial Failure Expectation:**
- Missing or mis-scoped `main.py`; import audit fails before implementation

**Post-Implementation Success Expectation:**
- Import audit passes with zero prohibited imports
- `main.py` imports from exactly the allowed module set

### V-005: Type Hints Contract

**Source Requirement ID:** FR-MAIN_TYPE_HINTS

**Verification Method:** UNIT_TEST

**Target:** Public function signatures in `main.py`

**Preconditions:**
- `main.py` exists at project root
- `mypy` or equivalent type-checking tool available, or fallback to AST inspection

**Input / Fixture:**
- Parse `main.py` public functions: `main()` and any others exposed in `__all__` or top-level
- Verify return type annotations are present on all public functions
- Verify parameter annotations are present on all parameters

**Expected Evidence:**
- Every public function has complete type annotations for parameters and return values
- Annotations reference concrete types from stdlib or imported modules

**Failure Condition:**
- Public function missing return annotation
- Public parameter missing type annotation

**Initial Failure Expectation:**
- Missing `main.py` causes static analysis to fail with file-not-found

**Post-Implementation Success Expectation:**
- Static analysis reports zero missing annotations on public functions

### V-006: Public Interface Contract

**Source Requirement ID:** FR-MAIN_ORCHESTRATION

**Verification Method:** UNIT_TEST

**Target:** Public exports of root `main.py`

**Preconditions:**
- `main.py` exists at project root

**Input / Fixture:**
- Import `main.py`
- Inspect public interface: `main()` and `__main__` guard presence
- Verify `__all__` if defined includes intended public symbols
- Verify calling `main()` returns int exit status

**Expected Evidence:**
- `main.py` exports `main()` callable
- `if __name__ == "__main__"` guard exists and calls `main()` or `exit(main())`
- Calling `main()` returns an `int` exit status

**Failure Condition:**
- `main()` is not importable
- `__main__` guard is missing
- `main()` returns non-int or raises unexpectedly

**Initial Failure Expectation:**
- Missing `main.py` causes import failure before implementation

**Post-Implementation Success Expectation:**
- Interface contract matches spec exactly
- Guarded execution works under `python3 main.py`

### V-007: Wrapper Integration Contract

**Source Requirement ID:** FR-MAIN_BACKWARD_COMPAT

**Verification Method:** INTEGRITY_TEST

**Target:** Integration between root `main.py`, `skills/healthcheck/healthcheck.py`, and `skills/healthcheck/index.js`

**Preconditions:**
- Root `main.py` exists
- `skills/healthcheck/healthcheck.py` wrapper exists
- `skills/healthcheck/index.js` wrapper exists

**Input / Fixture:**
- Execute `python3 skills/healthcheck/healthcheck.py` from project root
- Execute `node skills/healthcheck/index.js` or equivalent Node invocation
- Verify wrapper delegates to root `main.py`/`cli.py` behavior, not duplicated logic

**Expected Evidence:**
- Wrapper scripts execute successfully
- Wrapper output aligns with root module behavior
- No behavioral divergence between root invocation and wrapper invocation

**Failure Condition:**
- Wrapper invokes stale local modules instead of root modules
- Wrapper output diverges from root module output

**Initial Failure Expectation:**
- Missing root `main.py` causes wrapper integration failures before implementation

**Post-Implementation Success Expectation:**
- All wrapper integration paths succeed
- Behavior is consistent across direct root invocation and wrapper invocation
