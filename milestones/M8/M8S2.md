#### Objective

Extract skill discovery mechanisms from the monolithic `healthcheck.py` into a focused `discovery.py` module that locates skill directories containing `SKILL.md` files and detects the project root from any starting working directory. This module supplies the list of skill identifiers consumed by the orchestrator (M8S5) and the CLI (M8S4), while preserving the same discovery surface that the pre-refactor script exposed to user workflows.

##### Milestone Complexity & Multi-Spec Plan

Milestone M8 decomposes into exactly 5 sequential specifications:

- **M8S1** (completed): Core validation module (`core/validation.py`)
- **M8S2** (this spec): Discovery module (`discovery.py`)
- **M8S3**: Reporting module (`reporting.py`)
- **M8S4**: CLI module (`cli.py`)
- **M8S5**: Main entry point (`main.py`)

This spec addresses only HCS2 (Discovery). It MUST NOT redefine validation contracts from M8S1, nor reporting contracts from M8S3, nor CLI/main glue from M8S4/M8S5.

#### Functional Requirements

##### `FR-DISCOVERY_MODULE_EXPORTS`

* **Type**: Structured Schema Contract (Python module interface)
* **Interface Contract**: Module `discovery.py` exports a `discover_skills(project_root: Path | str) -> List[str]` function returning a deterministic, sorted list of skill directory names containing a `SKILL.md` file.
* **Expected Behavior**: The function accepts either a `pathlib.Path` or a `str`; returns a `list[str]` of skill directory basenames (not absolute paths), sorted lexicographically for stable ordering.
* **Observable Boundary**: `import discovery` succeeds; `discovery.discover_skills` is callable; input of `Path` or `str` yields identical results; output length equals the number of subdirectories that contain a `SKILL.md` file; output entries are strings.

##### `FR-PROJECT_ROOT_DETECTION`

* **Type**: Structured Schema Contract
* **Interface Contract**: Module `discovery.py` exports `find_project_root(start: Path | str | None = None) -> Path` that returns the project root directory by walking upward from `start` (defaulting to the current working directory) until a directory containing a recognized project marker is found.
* **Expected Behavior**: Recognized markers include (a) presence of a `skills/` subdirectory, (b) presence of a `package.json` file, or (c) presence of a `pyproject.toml` file. If no marker is found, the function returns the absolute path of the start directory. Returned path is always an absolute `pathlib.Path`.
* **Observable Boundary**: Function returns `pathlib.Path` instance; result is absolute (`is_absolute() == True`); result is a directory that exists on the filesystem.

##### `FR-SKILL_LISTING_FROM_FIXTURE`

* **Type**: Filesystem State Contract
* **Interface Contract**: Given a project root, `discover_skills` enumerates immediate subdirectories of `<project_root>/skills/` (per milestone integration binding `fixture: skills/`) and returns the names of those that contain a `SKILL.md` file.
* **Expected Behavior**: Subdirectories without a `SKILL.md` file are excluded. Hidden directories (names starting with `.`) are excluded. Symbolic links to directories are followed only if the resolved path is a directory. The function never raises on permission errors for individual subdirectories; entries that cannot be read are silently skipped.
* **Observable Boundary**: For a synthetic fixture containing N skill directories of which M contain a `SKILL.md` file, the returned list has exactly M entries; entry count matches fixture; each returned name matches the directory basename.

##### `FR-DISCOVERY_ERROR_TOLERANCE`

* **Type**: Structured Schema Contract
* **Interface Contract**: Discovery functions return structured results (lists or paths) and never raise unhandled exceptions for normal filesystem anomalies: missing `skills/` directory, empty `skills/` directory, unreadable subdirectory, or non-existent project root.
* **Expected Behavior**: If `<project_root>/skills/` does not exist, `discover_skills` returns an empty list. If a subdirectory is not readable, it is silently skipped (no exception bubbles to the caller). Empty-string or `None` input to `find_project_root` defaults to the current working directory.
* **Observable Boundary**: All error paths return their documented empty/default values; the function is total (no `raise` exits for documented error conditions); callers never need `try/except` for normal misuse.

##### `FR-DETERMINISTIC_SORT_ORDER`

* **Type**: Structured Schema Contract
* **Interface Contract**: `discover_skills` returns a list sorted lexicographically by skill directory basename using Python's default string ordering.
* **Expected Behavior**: The output list is monotonically non-decreasing under `<` comparison; the function is pure with respect to its input (same project root → same output list); no filesystem mutation occurs during execution.
* **Observable Boundary**: `result == sorted(result)` evaluates to `True`; calling the function twice on the same input yields identical lists (byte-equal).

##### `FR-SKILL_FIXTURE_PATH_RESOLUTION`

* **Type**: Filesystem State Contract
* **Interface Contract**: Module `discovery.py` exposes a constant or function `SKILLS_DIR_NAME = "skills"` representing the canonical skills directory name used by discovery.
* **Expected Behavior**: Discovery joins `project_root` with `SKILLS_DIR_NAME` to form the enumeration target; the constant is importable and equals `"skills"`.
* **Observable Boundary**: `from discovery import SKILLS_DIR_NAME` succeeds; `SKILLS_DIR_NAME == "skills"`.

#### Non-Functional Requirements

##### `NFR-DISCOVERY_MODULAR_INDEPENDENCE`

* **Constraint**: `discovery.py` MUST be importable and testable without importing `cli.py`, `reporting.py`, `main.py`, or `core.validation`. The only allowed cross-module dependency from `discovery.py` is to the Python standard library (`pathlib`, `os`, `typing`).
* **Verification**: Unit tests in `tests/M8/S2/test_discovery.py` import only `discovery` and standard library modules; no import of `cli`, `reporting`, `main`, or `core.validation` is present in either `discovery.py` or its test files.

##### `NFR-DISCOVERY_TYPE_HINTS`

* **Constraint**: All public functions and exported constants annotated with Python type hints (`Path`, `str`, `List[str]`, `Optional[Path]`).
* **Verification**: Static inspection via `typing.get_type_hints` confirms annotations on `discover_skills`, `find_project_root`, and the `SKILLS_DIR_NAME` constant.

##### `NFR-DISCOVERY_BACKWARD_COMPATIBILITY`

* **Constraint**: Discovery outputs are structurally equivalent to the pre-refactor `healthcheck.py` skill enumeration behavior: list of skill basenames, deterministic ordering, identical fixture source (`<project_root>/skills/`).
* **Verification**: Unit tests assert that the same fixture enumerated by the legacy `healthcheck.py` logic and by `discovery.discover_skills` produces the same set and ordering of skill names.

##### `NFR-DISCOVERY_NO_GLOBAL_STATE`

* **Constraint**: `discovery.py` MUST NOT rely on module-level mutable global state; all configuration flows through function parameters.
* **Verification**: Static inspection confirms no module-level mutable globals (lists, dicts, sets) are introduced; only immutable constants and function definitions are present at module scope.

#### Interface Boundaries

##### Module Thresholds

* `discovery.py` receives: a project root path (or starting directory for root detection) from the caller.
* `discovery.py` returns: a sorted `List[str]` of skill directory basenames, or an absolute `pathlib.Path` for the resolved project root.
* `discovery.py` consumes no environment variables; filesystem anchors are supplied via function arguments. The `skills/` subdirectory name is exposed as the importable constant `SKILLS_DIR_NAME`.

#### Assumptions

* A canonical `skills/` directory exists under the project root, containing one subdirectory per skill, each holding a `SKILL.md` file (per milestone integration binding `fixture: skills/`).
* `SKILL.md` files are validated downstream by `core.validation.SkillValidator` (M8S1); discovery does not parse file content.
* The host filesystem supports symbolic links (links resolved where present); otherwise links are silently skipped.
* Python interpreter (`python3`) available per milestone integration binding.
* Synthetic fixtures in `tests/fixtures/discovery/` provide a deterministic directory tree for unit testing.
