# Specification M8S3 - Reporting Module

This specification defines the Reporting Module for the HealthCheck Skill refactoring.

#### Objective

Create a reporting module (`reporting.py`) that provides:
- `generate_badges(results: List[Dict[str, Any]]) -> None` for badge generation
- `generate_health_report(results: List[Dict[str, Any]]) -> None` for JSON health reports
- `generate_processed_skills(results: List[Dict[str, Any]]) -> None` for processed skills JSON
- `generate_skills_summary(results: List[Dict[str, Any]]) -> Dict[str, Any]` for summary statistics
- All functions with proper type hints and deterministic behavior

#### Functional Requirements

All functional requirements must have semantic FR identifiers and be observable:

- **FR-REPORTING_MODULE_EXPORTS**: Module exports all required functions
- **FR-REPORTING_BADGE_GENERATION**: Generates health_badges.md with markdown table
- **FR-REPORTING_HEALTH_REPORT_JSON**: Generates health_check_report.json with schema
- **FR-REPORTING_PROCESSED_SKILLS_JSON**: Generates processed_skills.json mapping
- **FR-REPORTING_SKILL_SUMMARY_FUNCTION**: Returns dictionary with skill statistics
- **FR-REPORTING_MODULAR_INDEPENDENCE**: Module imports only from allowed dependencies
- **FR-REPORTING_TYPE_HINTS**: Complete Python type hints on all public functions
- **FR-REPORTING_DETERMINISTIC_OUTPUT**: Identical output on repeated invocations

#### Non-Functional Requirements

- **NFR-REPORTING_DETERMINISTIC**: Same input produces identical output
- **NFR-REPORTING_ERROR_HANDLING**: Graceful error handling and recovery
- **NFR-REPORTING_TESTABLE**: Independent unit testing capability
- **NFR-REPORTING_FILE_GENERATION**: Proper file creation and writing

#### Architecture Impact

**Allowlist (Files permitted to change):**
- `reporting.py` — New reporting module
- `tests/M8/S3/` — Unit tests for M8S3
- `tests/fixtures/reporting/` — Synthetic reporting test data
- `skills/healthcheck/main.py` — Update imports to use reporting.py

**Denylist (Do NOT Touch):**
- `core/validation.py` — Implemented in M8S1
- `discovery.py` — Implemented in M8S2
- `cli.py` — Implemented in M8S4
- `healthcheck.py` — Monolithic implementation being refactored
- `tests/M8/S1/`, `tests/M8/S2/`, `tests/M8/S4/` — Other module tests

#### Interface Boundaries

**Module Thresholds:**
- `reporting.py` reads: validation results, skills directory path
- `reporting.py` returns: None (side effects only)
- `reporting.py` consumes no external state
- `reporting.py` side effects: file creation in skills directory
