## Goal

Embed "The Mechanism" into the OMP AEF canonical architecture to enforce mechanical uncertainty markers, zero-trust reviews, evidence-based debugging, raw evidence mandates, and project-agnostic mechanical tooling gates.

---

## Motivation

Agents default toward generating forward progress over accuracy, guessing instead of verifying, and debugging by pattern-matching from memory. Furthermore, projects frequently suffer from environment-confusion bugs (e.g., Python/Node version mismatches) and silent type/schema drift because agents lack deterministic code-quality gates. We must make uncertainty a grep-able artifact, mandate evidence-based execution, and ensure every project establishes a local, mechanical tooling stack.

---

## Scope

1. **The Uncertainty Marker** — Update `FRAMEWORK.md`, `AGENTS.md`, and `skills/implement-specification/SKILL.md`. Mandate the use of a literal, grep-able marker: `#NEEDS-CLARIFICATION: <specific missing fact>`. If an agent's confidence in a fact is below "I could paste the command that proves this," it MUST either run the command immediately to prove it, or emit this marker and HALT. Guessing is strictly forbidden.

2. **Zero-Trust Review Pass** — Update `skills/review-implementation/SKILL.md` and `templates/review_template.md`. The reviewer agent must operate in a separate context from the implementer. Add the standing rule: _"Assume the prior report is wrong until proven otherwise. Verify every claim against the live state using bash or read commands."_

3. **Evidence-Based Debugging** — Update `skills/investigate-issue/SKILL.md` and `skills/evaluate-implementation/SKILL.md`. Add the standing rule: _"Debug from evidence, never from memory. The first action on any unfamiliar error is to read the literal message and use the tool's --help or introspection command. Never pattern-match from similar tools."_

4. **Raw Evidence Mandate** — Update `templates/completion_template.md` and `templates/evaluation_template.md`. Add a mandatory "Raw Evidence" section. Every "done" claim MUST ship with the exact terminal command and raw output that proves it succeeded.

5. **Ground-Truth Helper Utility** — Create a small, strictly read-only script (e.g., `bin/ground-truth-check.py` or `.sh`) in the AEF infrastructure. This tool will allow agents a low-friction way to quickly verify live state (e.g., file existence, database table existence, git status) to enable the zero-trust review discipline without writing complex bash one-liners.

6. **Agentic-Friendly Tooling Mandate** — Update `skills/bootstrap-project/SKILL.md` and `AGENTS.md`. Mandate that during project bootstrapping, the agent must advise and define a project-agnostic "Mechanical Tooling Stack" in the project's documentation. This must prompt the project to establish:
   - An **Environment Manager** (to prevent version ambiguity and auto-activate toolchains).
   - A **Fast Linter/Formatter** (to provide a deterministic gate an agent can auto-fix against).
   - A **Pre-commit Framework** (to run local gates automatically on every commit without cloud CI).
   - A **Type Checker** (to catch silent property/type mismatches before runtime).

---

## Out of Scope

- Do NOT create any new Python scripts with side-effects, enforcement logic, or state mutation. The only permitted new script is the read-only ground-truth check utility.
- Do NOT hardcode specific tooling brands (e.g., `mise`, `ruff`, `pre-commit`, `mypy`) into the OMP meta-framework as universal requirements. The mandate must advise the _categories_ of tools so the solution remains project- and language-agnostic.
- Do NOT alter the sequence of the existing Spec-Driven Development (SDD) pipeline.

---

## Success Criteria

- [ ] `#NEEDS-CLARIFICATION` is codified in `FRAMEWORK.md` and `AGENTS.md`.
- [ ] `review-implementation` explicitly requires live-state verification.
- [ ] `investigate-issue` explicitly forbids debugging from memory.
- [ ] Completion and Evaluation templates contain a mandatory "Raw Evidence" block.
- [ ] A read-only ground-truth check script exists and is documented for agent use.
- [ ] `bootstrap-project` enforces the definition of a mechanical tooling stack for all new projects.

---

## Risks

- **Resistance to cultural change**: Agents conditioned to "just make progress" may violate the HALT-on-uncertainty rule under time pressure. Requires reinforcement in multiple documents.
- **Scope creep into tool-specific mandates**: Without careful guardrails, the mechanical tooling stack could drift toward prescribing specific brands, violating the agnosticism requirement.
- **Ground-truth script maintenance**: A small utility that touches multiple project types could accrue feature requests and evolve into something with side-effects, violating the read-only constraint.

---

## Notes

- The name "The Mechanism" derives from the concept of mechanical determinism: inputs produce deterministic outputs with verifiable evidence at every step.
- All documents updated in this milestone should adopt consistent terminology: "mechanical uncertainty marker," "zero-trust review," "evidence-based debugging," "raw evidence mandate," and "mechanical tooling stack."
- The ground-truth utility should be intentionally minimal — a single file, no dependencies beyond stdlib.
