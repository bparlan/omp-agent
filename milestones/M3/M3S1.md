## Objective

Install Ladybug locally as a shared AEF skill and pilot a File/Symbol/IMPORTS graph on BariaDAO, with graph queries wired as a scripted verification gate that prevents out-of-scope edits at the verification stage.

### Milestone Complexity & Multi-Spec Plan

This milestone represents a complete end-to-end pipeline (installation, skill creation, parsing, verification hook, pilot). It is structured as a single specification (M3S1) because:
- V1 is a cohesive delivery with clear dependencies (cannot be split without breaking the pipeline)
- V2 is explicitly conditional and marked for followup after V1 validates the gating mechanism
- The scope is bounded by the negative guardrails and is complete within itself

## Functional Requirements

- **FR-1**: Install the `lbug` CLI locally using `curl -s https://install.ladybugdb.com | bash` and confirm it resolves on PATH in any shell that agent bash sessions inherit.
- **FR-2**: Add the Python client (`uv add ladybug`) to the AEF repo's environment and ensure it is available for scripted verification hooks.
- **FR-3**: Create a `graph-context` skill in `~/devcode/aef/agent/` that, when injected into a project, initializes `<project>/.omp/graph/<name>.lbug` and defines the V1 schema with `File` and `Symbol` node types and `IMPORTS` edge type only.
- **FR-4**: Write a parser that converts `skeleton.md` output into upsert operations against the V1 schema: one `File` node per `### File:` section, one `Symbol` node per `def`/`class`/`async def` line, and `IMPORTS` edges from each import statement (best-effort path resolution; flag unresolved imports rather than guessing).
- **FR-5**: Add a step to the `generate-verification` pipeline that, given a task's declared scope (files/components named in the spec), runs a direct Ladybug Python-client Cypher query for nodes reachable from the touched files and fails the task if the actual diff touches files outside that reachable set. This runs as plain pipeline code without agent tool calls or LLM judgment.
- **FR-6**: Verify that an agent session can run `lbug` directly via its bash tool against `<project>/.omp/graph/<name>.lbug` for ad hoc exploratory queries (e.g. "what does this file import") and document this as the sole agent-facing surface.
- **FR-7**: Run steps 2-6 end-to-end on BariaDAO to validate the complete pipeline and confirm the pilot graph is populated and queryable.

---

## Non-Functional Requirements

- **NFR-1**: The scripted verifier hook MUST fail at least one deliberately out-of-scope edit attempt to prove the gate is effective.
- **NFR-2**: The graph-context skill MUST be injectable into any AEF project without requiring external configuration.
- **NFR-3**: Import resolution MUST be conservative (flag unresolved imports rather than guessing paths) to avoid silent false positives.
- **NFR-4**: The verification hook MUST run deterministically as part of the generate-verification pipeline, without LLM involvement or tool selection decisions.
- **NFR-5**: The only agent-facing surface to the graph is bash access to `lbug` (no MCP tools, no agent-facing APIs) to avoid schema-ambiguity risks.
- **NFR-6**: The pilot on BariaDAO MUST succeed in populating the graph from its current skeleton.md without errors or data loss.

## Data Flow

```
skeleton.md (project output)
  ↓
graph-context parser (upserts to .omp/graph/<name>.lbug)
  ↓
Ladybug Python client (Cypher queries)
  ↓
generate-verification hook (scripted, non-LLM)
  ↓
Decision: Pass (diff within reachable set) or Fail (diff outside reachable set)
```

## Implementation Tasks

1. **Tooling installation**:
   - Run `curl -s https://install.ladybugdb.com | bash` to install `lbug` CLI
   - Verify `lbug --version` works in a shell that agents inherit
   - Add Python client: `cd ~/devcode/aef/agent && uv add ladybug`
   - Test Python client imports: `python -c "import ladybug; print('OK')"`

2. **graph-context skill creation**:
   - Create `~/devcode/aef/agent/skills/graph-context/` directory
   - Write SKILL.md with injectability instructions and usage documentation
   - Implement graph initialization: create `.omp/graph/<name>.lbug` with V1 schema (File, Symbol, IMPORTS)
   - Implement skeleton.md parser: read `### File:` sections → create File nodes; read `def`/`class`/`async def` → create Symbol nodes; parse imports → create IMPORTS edges

3. **generate-verification modification**:
   - Read generate-verification SKILL.md to understand current flow
   - Add new verification step that accepts declared scope (files/components from spec)
   - Query reachable nodes from those files using Ladybug Python client Cypher
   - Diff actual changes and fail if they touch files outside reachable set
   - Ensure the step runs as plain code (no LLM, no tool selection)

4. **Bash access verification**:
   - Document the only agent-facing surface: bash execution of `lbug` queries
   - Create a test script demonstrating query (e.g., find all files a target file imports)
   - Verify agent bash tool can run it against the pilot graph

5. **BariaDAO pilot**:
   - Create `.omp/graph/baria.lbug` in BariaDAO project
   - Run graph-context skill to initialize schema
   - Run skeleton.md parser to populate graph
   - Verify graph queryability with sample queries
   - Run generate-verification with a task that stays in-scope (should pass)
   - Deliberately create an out-of-scope edit and verify the verification hook fails it
