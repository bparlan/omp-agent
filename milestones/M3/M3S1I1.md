## Objective

Stabilize M3S1 Graph-Based Scope Verification implementation by fixing critical schema, parsing, and integration issues identified in the investigation report.

This is a fix-up specification for M3S1 addressing critical stability issues that prevent the verification mechanism from functioning correctly. It is structured as a standalone specification (M3S1I1) because:

- Fixes are independent and can be applied in any order

- Does not expand the scope beyond M3S1's original V1 objectives

### Remaining Gaps

**Critical Issues Identified** (from M3S1_INVESTIGATION.md):

1. **Schema Property Mismatch**: ingest-skeleton.py uses `fileId` property, but lbug database schema uses `file2` - causes all Symbol node queries to fail
2. **Incomplete Skeleton Parsing**: ingest-skeleton.py only parses imports as text, doesn't create IMPORTS edges between File nodes
3. **Minimal Graph Population**: Graph has only 2 File nodes despite skeleton.md containing 3 files
4. **Disintegrated Verification Workflow**: verify-scope.py is standalone CLI tool, not integrated with graph-context workflow
5. **Test Coverage Gap**: Tests expect graph-based verification that doesn't exist

**Impact**:
- Current implementation cannot reliably verify scope compliance
- FR-6 scripted verification hook fails (doesn't query graph)
- All Symbol node queries fail (property mismatch)
- IMPORTS edges missing (no dependency resolution)
- Graph doesn't reflect project structure accurately
