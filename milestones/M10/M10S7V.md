#### Success Criteria

The implementation of the Safe-to-Proceed Implementation Gate is successful when:

- [ ] `bin/omp-verify-readiness` exists and is executable.
- [ ] `bin/omp-verify-readiness` returns exit code 0 when user approval is present and tests are valid.
- [ ] `bin/omp-verify-readiness` returns exit code 1 when user approval is absent or tests are invalid (such as syntax errors).
- [ ] `bin/omp-verify-readiness` returns exit code 2 when invalid paths or incorrect argument structures are provided.
- [ ] `implement-specification` executes the readiness check as its very first action and fails-closed on non-zero exit codes.

#### Functional Validation

##### V-FR-1 — CLI Contract and Arguments

- **Source Requirement:** FR-1
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** bin/omp-verify-readiness
- **Preconditions:**
  - The specification file milestones/M10/M10S7.md exists and is readable.
  - A test directory tests/M10/ exists and contains valid or invalid test states.
  - The bin/omp-verify-readiness script is executable.
- **Input or Fixture:**
  - Command arguments: --spec milestones/M10/M10S7.md --test-dir tests/M10/
- **Expected Evidence:**
  - **Exit Code 0 (PASS):**
    - The milestones/M10/M10S7.md file contains the exact user approval stamp: #### User Approval\n\* [x] Approved for implementation by user.
    - The tests/M10/ directory's test state is valid (passing or VALID_INITIAL_FAILURE).
  - **Exit Code 1 (BLOCKED):**
    - The milestones/M10/M10S7.md file is missing the exact user approval stamp.
    - OR the tests/M10/ directory's test state is invalid (e.g., syntax errors, compilation failures, corrupted fixtures).
    - Expected stderr message when approval is missing: BLOCKED: Specification lacks human approval.
  - **Exit Code 2 (VALIDITY_FAILURE):**
    - The specified --spec path is invalid or unreadable.
    - OR the specified --test-dir path is invalid or unreadable.
- **Failure Condition:** The bin/omp-verify-readiness command exits with an unexpected code or produces incorrect stderr messages based on the defined preconditions and inputs.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127 Command Not Found)
- **Post-Implementation Success Expectation:** PASS

##### V-FR-2 — Specification Approval Stamp Verification

- **Source Requirement:** FR-2
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** bin/omp-verify-readiness
- **Preconditions:**
  - The bin/omp-verify-readiness command is executed with the --spec argument pointing to milestones/M10/M10S7.md.
- **Input or Fixture:** The content of milestones/M10/M10S7.md.
- **Expected Evidence:**
  - The script MUST detect the presence of the literal string `#### User Approval\n* [x] Approved for implementation by user` anywhere within the specification file.
  - If the stamp is absent, stderr MUST contain the exact message `BLOCKED: Specification lacks human approval`.
- **Failure Condition:** The script fails to detect the correct approval stamp when present, or fails to report the specific stderr message when the stamp is absent.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
- **Post-Implementation Success Expectation:** PASS

##### V-FR-3 — Test Readiness State Verification

- **Source Requirement:** FR-3
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** bin/omp-verify-readiness
- **Preconditions:**
  - The bin/omp-verify-readiness command is executed with the --test-dir argument pointing to a valid directory.
  - The state of the tests within the specified test directory is known (e.g., valid, invalid syntax, missing files).
- **Input or Fixture:** The state of the tests within the tests/M10/ directory.
- **Expected Evidence:**
  - The script MUST correctly assess the state of the tests in tests/M10/.
  - If the test state is valid (passing or VALID_INITIAL_FAILURE), the script should not exit with code 1 or 2 due to test state issues.
  - If the test state is invalid (e.g., syntax errors, compilation failures), the script MUST exit with code 1.
- **Failure Condition:** The script incorrectly assesses the test readiness state, or exits with an incorrect code based on the test state.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
- **Post-Implementation Success Expectation:** PASS
