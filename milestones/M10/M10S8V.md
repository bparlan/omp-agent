#### Success Criteria
The implementation of the Failure Classification & Diagnostic Contract is successful when:
*   [ ] `bin/omp-test` performs a pre-flight validation check on specification files using `validate_metadata.py` before executing tests.
*   [ ] `bin/omp-test` immediately aborts and suppresses all downstream project execution strategies when a validation check fails.
*   [ ] `bin/omp-test` logs a single, standardized, high-fidelity `VALIDITY_FAILURE` message to `stderr` upon pre-flight failure.
*   [ ] `bin/omp-test` completely hides raw multiline Python tracebacks from the standard terminal console upon pre-flight failure.
*   [ ] `bin/omp-test` redirects and appends the full, unsuppressed, verbose traceback and raw output logs to `/workspace/scratch/diagnostic_run.log`.
*   [ ] `bin/omp-test` exits with code 2 on pre-flight validity failure.

#### Functional Validation

##### V-FR-1 — Core Dependency Validation and Assertion Suppression
*   **Source Requirement:** FR-1
*   **Verification Method:** SCRIPT_EXECUTION
*   **Target:** `bin/omp-test`
*   **Precondition:** `bin/omp-test` is implemented and executable. A malformed specification file exists in the target path.
*   **Input or fixture:** Invoke `bin/omp-test --path tests/fixtures/synthetic_project_docs/` (where we plant a malformed spec file lacking YAML frontmatter).
*   **Expected Evidence:** Invoking the command immediately aborts test execution. No individual markdown test strategy runs, and the stdout test summary reports `TESTS_RUN=0`, `TESTS_PASSED=0`, `TESTS_FAILED=0`.
*   **Failure Condition:** The tool attempts to execute Markdown tests on the malformed specification directory, prints passing results, or does not halt immediately.
*   **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127 Command Not Found)
*   **Post-Implementation Success Expectation:** PASS

##### V-FR-2 — Standardized Single-Line Diagnostics Summary
*   **Source Requirement:** FR-2
*   **Verification Method:** SCRIPT_EXECUTION
*   **Target:** `bin/omp-test`
*   **Precondition:** `bin/omp-test` is implemented and executable.
*   **Input or fixture:** Run `bin/omp-test --path tests/fixtures/synthetic_project_docs/` (with a malformed spec file).
*   **Expected Evidence:** The console `stderr` output contains exactly one line formatted as: `VALIDITY_FAILURE: No valid YAML frontmatter found in...`. No multiline python exception traces are written to `stdout` or `stderr`.
*   **Failure Condition:** The stderr stream is empty, contains multiple lines, displays raw Python traceback text, or the diagnostic message is improperly formatted.
*   **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
*   **Post-Implementation Success Expectation:** PASS

##### V-FR-3 — Traceback and Verbose Log Isolation
*   **Source Requirement:** FR-3
*   **Verification Method:** SCRIPT_EXECUTION
*   **Target:** `bin/omp-test`
*   **Precondition:** The directory `/workspace/scratch/` exists and is writable.
*   **Input or fixture:** Execute `bin/omp-test --path tests/fixtures/synthetic_project_docs/` (with a malformed spec file).
*   **Expected Evidence:** The file `/workspace/scratch/diagnostic_run.log` physically exists, is non-empty, and contains the full, verbose Python traceback output containing `validate_metadata.py` stack details.
*   **Failure Condition:** The log file is missing, remains empty, or does not contain the unsuppressed traceback of the failing dependency.
*   **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
*   **Post-Implementation Success Expectation:** PASS

#### Edge Cases
*   **Missing Log Directory:** If `/workspace/scratch/` is missing, the tool must safely initialize it using `os.makedirs` without crashing.
*   **Multiple Metadata Failures:** If multiple specification files are malformed, the single-line summary on `stderr` must report the first encountered failure path gracefully.

--------------------------------------------------------------------------------

#### Failure Scenarios
*   **Empty Specification File:** If a spec file is completely empty, the tool must handle the exception, write `VALIDITY_FAILURE: No valid YAML frontmatter found in <path>`, log the details to scratch, and exit with code 2.
