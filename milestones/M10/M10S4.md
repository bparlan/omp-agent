## Objective

This specification defines the contract for the `generate-tests` skill, ensuring that tests generated are directly traceable to the verification protocol and the overarching specification. It dictates the format of the test plan output and the header comments within generated test scripts.

### Milestone Complexity & Multi-Spec Plan

This milestone (M10) is decomposed into 10 sequential specifications. This is the fourth specification (S4) in that series. No further breakdown is required for this step.

## Functional Requirements

### FR-1: Test Plan Output Contract
The `generate-tests` skill MUST output a test plan.
*   **Contract**: The test plan file must be named `M10S<N>T<X>.md`, where `<N>` is the current specification sequence number (4 for this spec) and `<X>` is the test set sequence number (e.g., 1).
*   **Observable Behavior**: The file must be created in the `milestones/M10/` directory and conform to the schema defined in FR-2.

### FR-2: Test Plan Schema
The test plan Markdown file (`M10S<N>T<X>.md`) MUST contain a deterministic mapping.
*   **Contract**: The file must contain a Markdown table with the following columns: `Test File`, `Verification ID`, `Requirement ID`.
*   **Observable Behavior**: The table must be parsable and contain accurate mappings from the generated test file path to its corresponding Verification ID and Requirement ID from the preceding verification protocol.

### FR-3: Test Script Header Contract
Every generated test script (`.sh` or `.py`) MUST begin with specific comment headers.
*   **Contract**: Test scripts must start with precisely formatted comments:
    ```
    # {Verification IDs: V-FR-X}
    # {Requirement IDs: FR-X}
    ```
    Where `V-FR-X` and `FR-X` are the specific IDs derived from the test plan (FR-2) and the verification protocol.
*   **Observable Behavior**: The first lines of any generated executable test script must match this format, with valid IDs.

### FR-4: Traceability Enforcement
The `generate-tests` skill MUST ensure that the IDs in the test script headers (FR-3) are traceable to the `Verification ID` and `Requirement ID` columns in the test plan (FR-2).
*   **Observable Behavior**: The skill must validate that for every test generated, the `Verification ID` and `Requirement ID` present in its header comments can be found in the corresponding columns of the generated test plan.

## Non-Functional Requirements

*   **NFR-1: Determinism**: Test generation must be deterministic; given the same verification protocol and specification, the same set of tests and test plan must be produced.

## Data Flow

*   **Input**: Verification protocol (`M10S<N>V.md`), Specification (`M10S4.md`), and potentially `M10.md` for context.
*   **Processing**: The `generate-tests` skill processes these inputs to:
    1.  Determine required tests based on verification items.
    2.  Generate test scripts with correct headers.
    3.  Create a test plan mapping test files to their source Verification and Requirement IDs.
*   **Output**: Test plan file (`M10S<N>T<X>.md`) and generated test scripts in the appropriate test directory.

## Constraints

*   Test generation must directly derive IDs from the verification protocol and specification.
*   Generated test scripts must be syntactically valid for their respective languages (.sh, .py).
*   Traceability must be bi-directional between test scripts, test plan, verification, and specification.
