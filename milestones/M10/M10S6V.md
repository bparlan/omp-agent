#### Success Criteria

The implementation of the project-agnostic test execution contract is successful when:

- [ ] `bin/omp-test` CLI exists, is executable, and accepts optional `--path` and `--test-dir` arguments.
- [ ] `bin/omp-test` dynamically integrates with `bin/omp-discover` to extract `project_kind` and `capabilities` without hardcoding project context.
- [ ] `bin/omp-test` routes test execution dynamically to adaptive strategies (Markdown frontmatter, Static site DOM/classes, Python pytest, and AEF bash tasks).
- [ ] `bin/omp-test` strictly logs a clean, machine-readable key-value block to stdout specifying `TESTS_RUN`, `TESTS_PASSED`, `TESTS_FAILED`, `VALID_TESTS`, `INVALID_TESTS`, and `EXIT_CODE`.
- [ ] `bin/omp-test` enforces a strict 30-second execution boundary timeout per test.
- [ ] All tests execute against static, isolated fixtures in a read-only state.
- [ ] No test oracles use regex parsing on diagnostic prose outputs.

#### Functional Validation

##### V-FR-1.1 — CLI Command and Arguments

- **Source Requirement:** FR-1
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** `bin/omp-test`
- **Precondition:** The workspace directory contains `bin/omp-test` as an executable binary/script.
- **Input or fixture:** None
- **Expected Evidence:** Invoking `bin/omp-test --help` or `bin/omp-test` runs successfully, prints CLI options on stdout/stderr, and returns exit code 0 or 2 (for empty paths/missing configuration but never 127).
- **Failure Condition:** Command not found, permission denied, or argument parser throws unhandled exception on `--path` and `--test-dir`.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127 Command Not Found)
- **Post-Implementation Success Expectation:** PASS

##### V-FR-1.2 — CLI Exit Codes Semantics

- **Source Requirement:** FR-1
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** `bin/omp-test`
- **Precondition:** `bin/omp-test` is implemented and executable. Static test fixtures are available.
- **Input or fixture:** A project containing passing tests, a project containing failing assertions, and a project containing syntax/invalid test defects.
- **Expected Evidence:**
  1. Running on a passing project yields `exit code 0`.
  2. Running on a project with assertion failures yields `exit code 1`.
  3. Running on a project with syntax errors/invalid scripts yields `exit code 2`.
- **Failure Condition:** The tool returns exit code 0 for failing scripts, returns exit code 1 for invalid test syntax, or crashes with Python tracebacks.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127 Command Not Found)
- **Post-Implementation Success Expectation:** PASS

##### V-FR-2.1 — Dynamic Project Resolution

- **Source Requirement:** FR-2
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** `bin/omp-test`
- **Precondition:** `bin/omp-discover` is functional in the path and accessible.
- **Input or fixture:** Invoke on `tests/fixtures/synthetic_project_python/` (which contains a Python package).
- **Expected Evidence:** `bin/omp-test` runs `bin/omp-discover --path tests/fixtures/synthetic_project_python/`, parses the JSON returned, identifies the `project_kind` as `python` (or `generic` with python capabilities), and executes the python testing loop.
- **Failure Condition:** If `bin/omp-discover` is missing, returns invalid JSON, or fails, the tool fails to handle the exception, crashes, or defaults to an incorrect strategy instead of returning exit code 2 (VALIDITY_FAILURE).
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
- **Post-Implementation Success Expectation:** PASS

##### V-FR-4.1 — Standardized Execution Summary

- **Source Requirement:** FR-4
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** `bin/omp-test`
- **Precondition:** Verification scripts are configured to read from stdout.
- **Input or fixture:** Execution run on any of the static fixtures.
- **Expected Evidence:** The console output displays the metrics block on clean isolated lines matching:
  ```text
  TESTS_RUN=\d+
  TESTS_PASSED=\d+
  TESTS_FAILED=\d+
  VALID_TESTS=\d+
  INVALID_TESTS=\d+
  EXIT_CODE=[6]
  ```
- **Failure Condition:** Metrics are missing, use custom wording, print inline debug code on the same lines, or fail to output keys exactly as specified in the contract.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
- **Post-Implementation Success Expectation:** PASS

- **Failure Condition:** The tool writes temp files, creates `.exit_code` files in target project directories, or mutates any files under test.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
- **Post-Implementation Success Expectation:** PASS

##### V-NFR-1.1 — Execution Boundary Timeout

- **Source Requirement:** NFR-1
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** `bin/omp-test`
- **Precondition:** A mock hanging test script is registered in the test suite directory that sleeps indefinitely.
- **Input or fixture:** A test script executing `sleep 60` or equivalent infinite loop.
- **Expected Evidence:** Invoking `bin/omp-test` executes the script, triggers the 30-second boundary timeout, halts the subprocess cleanly, logs the boundary failure as a VALIDITY_FAILURE, and exits with code 2.
- **Failure Condition:** The test runner hangs indefinitely (exceeding 30 seconds), leaks zombie subprocesses, or fails to terminate the script cleanly.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
- **Post-Implementation Success Expectation:** PASS

##### V-NFR-2.1 — Oracle Independence

- **Source Requirement:** NFR-2
- **Verification Method:** DOCUMENT_CHECK
- **Target:** All generated test scripts for `bin/omp-test` in `tests/M10/`
- **Precondition:** Test files are generated.
- **Input or fixture:** `tests/M10/*` content on disk.
- **Expected Evidence:** Test files assert numeric exit codes or parse returned structured schemas. No test file utilizes text-searching utilities or matches regular expressions against human-readable diagnostic prose.
- **Failure Condition:** Test files perform substring scanning or raw pattern searches on command output prose to determine test outcomes.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_NOT_POSSIBLE
- **Post-Implementation Success Expectation:** PASS
