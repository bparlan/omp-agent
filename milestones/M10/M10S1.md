## Functional Requirements

- **FR-1**: The system shall provide a mechanism for understanding the project context without assuming specific technology, structure, or domain.
    - **FR-1.1**: Implement a CLI tool named `bin/omp-discover`.
    - **FR-1.2**: `bin/omp-discover` shall accept an optional `--path <target_directory>` argument.
    - **FR-1.3**: `bin/omp-discover` shall exit with a status code of 0 upon successful profiling of the target directory.
    - **FR-1.4**: `bin/omp-discover` shall exit with a status code of 1 if an invalid path is provided.
    - **FR-1.5**: `bin/omp-discover` shall output project metadata in JSON format adhering to the specified schema.
    - **FR-1.6**: Verification of `bin/omp-discover` shall utilize the following static test fixtures: `tests/fixtures/synthetic_python/`, `tests/fixtures/synthetic_static/`, `tests/fixtures/synthetic_docs/`.
    - **FR-1.7**: The test oracle for `bin/omp-discover` shall assert keys and structures programmatically using `jq` or JSON parsing tools, avoiding text-based regex matching on output prose.

## Data Flow

The `bin/omp-discover` tool takes a directory path as input and outputs a JSON object containing project metadata:
```json
{
  "project_slug": "my-app",
  "project_kind": "application | framework | hybrid",
  "capabilities": ["python", "static_site", "documentation", "mixed"],
  "artifact_root": "./milestones",
  "active_skills_path": "./agent/skills"
}
```

## Implementation Tasks

1. Implement the `bin/omp-discover` CLI tool.
2. Implement argument parsing for `--path <target_directory>`.
3. Implement logic to determine `project_slug`, `project_kind`, `capabilities`, `artifact_root`, and `active_skills_path`.
4. Implement JSON output generation adhering to the specified schema.
5. Implement exit code semantics for success (0) and invalid path (1).
6. Ensure test fixtures are correctly referenced and utilized.
7. Implement programmatic assertion of output keys and structures.
