## Technical Debt

1. **Qualifier detection approach**: Uses a whitelist of known qualifier words (`CORRECTED`, `FINAL`, `FIXED`, `REVISED`) plus a `V\d+` version pattern. This was a deliberate tradeoff — broader regex matching (e.g., "any hyphenated suffix composed entirely of uppercase letters or digits") incorrectly flags valid IDs like `SPEC-M10S1`. If new qualifier conventions emerge, the set needs updating.

2. **Tool bloat in `bin/`**: This tool joins `validate_metadata.py` and `resolve_artifact.py` as a third Python utility with overlapping concerns. `validate_metadata.py` uses a different schema with fields like `status` and `title` that this tool intentionally omits per the M10S2 spec. Future consolidation into a single metadata validation library may be warranted.

3. **Error message consistency**: Error messages are human-readable and on stderr, but not structured (no JSON output, no machine-parseable error codes). Acceptable per spec (stderr is diagnostic-only), but downstream automation may benefit from structured error output.

4. **No help/usage flag**: The tool prints usage when called with zero arguments, but has no `--help` flag. Not required by the spec, but a minor ergonomic gap.
