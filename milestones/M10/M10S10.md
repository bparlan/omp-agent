#### Objective

Ensure bin/omp-verify-metadata gracefully supports backward compatibility with legacy OMP/AEF repositories [1]. The validator must handle historical milestone folders lacking YAML frontmatter without breaking execution or silently mutating files [1].

---

#### Functional Requirements

- **FR-1 — Legacy Document Graceful Handling:**
  - When called on an artifact path, the tool must first scan for a frontmatter block.
  - If the file contains no frontmatter and is located under a legacy folder (e.g., milestones/M1/ through milestones/M9/, or milestones/archive/), the tool must bypass schema enforcement and report the file as LEGACY_COMPATIBLE (returning exit code 0) instead of crashing [1].
- **FR-2 — Active Milestone Metadata Enforcement:**
  - If a file is located in the active milestones directory (milestones/M10/ or tests/) and lacks a valid frontmatter schema, the validator must strictly reject it and exit with code 1.
- **FR-3 — Legacy Exclusions Configuration:**
  - The tool must read an optional local JSON configuration file .omp/legacy_exclusions.json listing historic files that are exempt from frontmatter validation.

#### Architecture Impact

##### Strict File Scope (Allowlist & Denylist)

**Allowlist (Files permitted to change):**

  **Denylist (Do NOT Touch):**

#### Acceptance Criteria

- [ ] bin/omp-verify-metadata exits with code 0 on legacy milestone files lacking frontmatter.
- [ ] bin/omp-verify-metadata exits with code 1 on active M10 files lacking frontmatter.
- [ ] bin/omp-verify-metadata respects exclusions defined in .omp/legacy_exclusions.json.
