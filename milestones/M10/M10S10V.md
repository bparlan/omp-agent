#### Success Criteria

The implementation of the Multi-Project Compatibility & Migration Contract is successful when:

- [ ] bin/omp-verify-metadata gracefully handles legacy documents lacking YAML frontmatter by returning exit code 0 under a "legacy compatibility layer."
- [ ] bin/omp-verify-metadata strictly enforces canonical metadata validation (exit code 1) ONLY for newly generated milestone files under M10.

#### Functional Validation

##### V-FR-1 — Legacy Document Graceful Handling

- **Source Requirement:** FR-1
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** bin/omp-verify-metadata
- **Preconditions:** A legacy markdown file exists that contains NO YAML frontmatter block.
- **Input or fixture:** A dummy file milestones/M9/legacy_document.md containing only plain text.
- **Expected Evidence:** Running bin/omp-verify-metadata milestones/M9/legacy_document.md identifies the file as a legacy document, skips it gracefully, and exits with code 0.
- **Failure Condition:** The tool crashes or exits with code 1 for the legacy document.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (Exit Code 1)
- **Post-Implementation Success Expectation:** PASS

##### V-FR-2 — New Artifact Metadata Enforcement

- **Source Requirement:** FR-2
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** bin/omp-verify-metadata
- **Preconditions:** A newly generated milestone file exists in milestones/M10/.
- **Input or fixture:** A dummy file milestones/M10/M10S10_dummy.md containing no frontmatter.
- **Expected Evidence:** Running the validator against the active milestone file detects the missing schema and strictly exits with code 1.
- **Failure Condition:** The validator skips the active milestone file or allows it to pass with exit code 0.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (Exit Code 0)
- **Post-Implementation Success Expectation:** PASS
