# Specification: M10S3 - Traceability Enforcement Tool

## Objective

This specification defines the behavior and interface contract for a new command-line utility, `bin/omp-verify-traceability`, designed to enforce bi-directional traceability between specification documents and their corresponding verification protocols. This is the third specification (S3) for milestone M10.

## Functional Requirements

### FR-1: CLI Executable Contract
The system MUST provide a CLI executable at `bin/omp-verify-traceability`.
*   **Contract**: `bin/omp-verify-traceability --spec <spec_file_path> --verification <verification_file_path>`
*   **Observable Behavior**: The tool must accept `--spec` and `--verification` arguments, which are file paths to Markdown documents.

### FR-2: Success Exit Semantics
The `bin/omp-verify-traceability` tool MUST exit with status code `0` under the following conditions:
*   All functional requirements defined in the `--spec` file exist and are mapped to a corresponding verification item in the `--verification` file.
*   All verification items defined in the `--verification` file correspond to an active functional requirement in the `--spec` file.
*   All active functional requirements (those representing active CLI/API code-under-test) are verified by `SCRIPT_EXECUTION` or `UNIT_TEST` types within the verification protocol.

### FR-3: Failure Exit Semantics
The `bin/omp-verify-traceability` tool MUST exit with status code `1` under any of the following conditions:
*   The `--spec` file path provided does not exist.
*   The `--verification` file path provided does not exist.
*   The `--spec` file has invalid Markdown formatting.
*   The `--verification` file has invalid Markdown formatting.
*   The `--spec` file contains orphan functional requirements (requirements not mapped to any verification item).
*   The `--verification` file contains invented or orphan verification items (items not mapped to any active functional requirement).
*   An active functional requirement (representing CLI/API code-under-test) is verified using a passive `DOCUMENT_CHECK` in the verification protocol.

*   CLI command: `bin/omp-verify-traceability`

## Data Flow

*   **Input**: File paths to specification and verification documents.
*   **Processing**: The tool parses both documents, identifies requirements and verification items, and checks for bi-directional mapping and appropriate verification types.
*   **Output**: A single exit code (0 for success, 1 for failure).

## Constraints

*   Specifications must define observable boundaries (CLI, Schema, Filesystem).
*   Requirements must NOT be defined by prose wording alone.
*   Verification items must map to existing, active requirements.
*   Active requirements must use specific verification types (`SCRIPT_EXECUTION`, `UNIT_TEST`), not `DOCUMENT_CHECK`.
*   Specifications and verification protocols must adhere to valid Markdown formatting.
