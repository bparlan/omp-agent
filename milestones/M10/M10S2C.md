#### 3. Technical Changes Summary

Created `bin/omp-verify-metadata` — a Python CLI tool that validates YAML frontmatter against the M10S2 canonical schema contract:

- **FR-1:** CLI tool `bin/omp-verify-metadata <file1> [file2 ...]` — exits 0 if all valid, 1 if any invalid or missing.
- **FR-2:** Schema validation for 5 fields:
  - `id` — non-empty string, rejects semantic qualifiers (`-CORRECTED`, `-FINAL`, `-FIXED`, `-REVISED`) and version markers (`-V2`, `-V3`)
  - `type` — enum: `specification`, `verification`, `test_set`, `completion`, `evaluation`, `review`, `milestone`
  - `milestone_id` — non-empty string
  - `derived_from` — optional array of strings
  - `supersedes` — optional array of strings
- **FR-3:** Tests assert exit codes programmatically, not prose. Static fixtures in `tests/fixtures/synthetic_metadata_{valid,invalid}/`.

Leverages existing `bin/_frontmatter.py` for YAML extraction.

#### 4. Edge Cases Handled

| Edge Case | Behavior |
|-----------|----------|
| File does not exist | Exit 1, error on stderr |
| No YAML frontmatter (no `---`) | Exit 1, error on stderr |
| Empty `id` (`""`) | Exit 1, error on stderr |
| Empty `milestone_id` (`""`) | Exit 1, error on stderr |
| `id` with `-CORRECTED` suffix | Exit 1, error on stderr |
| `id` with `-FINAL` suffix | Exit 1, error on stderr |
| `id` with `-V2` / `-V3` version marker | Exit 1, error on stderr |
| `id` with `-FIXED` / `-REVISED` suffix | Exit 1, error on stderr |
| `type` not in allowed enum | Exit 1, error on stderr |
| `derived_from` present but not a list | Exit 1, error on stderr |
| `supersedes` present but not a list | Exit 1, error on stderr |
| Valid artifact with `SPEC-M10S1` (plain ID) | Exit 0 — correctly passes |
| Valid artifact with `derived_from` array | Exit 0 — correctly passes |
| Valid artifact with `supersedes` array | Exit 0 — correctly passes |
| Multiple files (mixed valid + invalid) | Exit 1 — overall failure |
| Multiple files (all valid) | Exit 0 — overall success |

All error messages are human-readable, written to stderr, and exit code is the deterministic oracle.

#### 5. Identified Technical Debt

- The qualifier detection uses a whitelist of known qualifier words (`CORRECTED`, `FINAL`, `FIXED`, `REVISED`) plus a `V\d+` version pattern. If new qualifier conventions emerge, the set needs updating. A regex-based approach with broader matching was considered but rejected because it would incorrectly flag valid IDs like `SPEC-M10S1` (where `S1` is a valid sequence identifier, not a qualifier).
- The tool currently operates only on explicit file paths. Future specs (M10S9/M10S10) may add directory scanning or Git integration.
- `bin/validate_metadata.py` (a pre-existing utility) has a different schema with different required fields. The two tools serve complementary purposes — `validate_metadata.py` for the legacy convention, `omp-verify-metadata` for the M10S2 canonical contract. Future consolidation may be warranted.
