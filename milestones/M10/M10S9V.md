#### Success Criteria

The implementation of the Artifact Persistence & Git Integrity Contract is successful when:

- [ ] `bin/omp-verify-git-integrity` exists, is executable, and accepts `--ledger` positional/keyword arguments.
- [ ] `bin/omp-verify-git-integrity` successfully identifies untracked (`??`) files and returns exit code 1.
- [ ] `bin/omp-verify-git-integrity` returns exit code 0 when all parsed files are staged/tracked.
- [ ] `bin/omp-verify-git-integrity` returns exit code 2 when executed outside a Git repository or with invalid arguments.
- [ ] `bin/omp-verify-precondition` integrates the check and fails-closed on Git integrity failures.

#### Functional Validation

##### V-FR-1 — CLI Contract and Argument Parsing

- **Source Requirement:** FR-1
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** `bin/omp-verify-git-integrity`
- **Preconditions:**
  - The test plan ledger `milestones/M10/M10S9T1.md` exists and is readable.
- **Input or fixture:** `--ledger milestones/M10/M10S9T1.md`
- **Expected Evidence:** Invoking the tool runs successfully, prints results, and returns exit code 0 if files are tracked, or 1 if untracked. Missing the ledger argument results in exit code 2.
- **Failure Condition:** Command crashes, fails to parse arguments, or returns exit code 0 when required arguments are missing.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127 Command Not Found)
- **Post-Implementation Success Expectation:** PASS

##### V-FR-2 — Git Status short Code Matching

- **Source Requirement:** FR-2
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** `bin/omp-verify-git-integrity`
- **Preconditions:**
  - Executed inside an active Git repository.
  - A test plan ledger contains paths to both tracked and untracked files.
- **Input or fixture:** A mock ledger file listing:
  1. A tracked file (`README.md`).
  2. A newly created, untracked file (`tests/M10/test_mock_untracked.sh`).
- **Expected Evidence:**
  - Running on clean/tracked files returns exit code 0.
  - Creating the untracked file and executing the tool returns exit code 1.
- **Failure Condition:** The tool returns exit code 0 for untracked files, or fails to execute Git as a subprocess.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
- **Post-Implementation Success Expectation:** PASS

##### V-FR-3 — Precondition Gate Hook Verification

- **Source Requirement:** FR-3
- **Verification Method:** SCRIPT_EXECUTION
- **Target:** `bin/omp-verify-precondition`
- **Preconditions:**
  - The precondition verifier is updated to hook the Git integrity verifier.
- **Input or fixture:** Run `bin/omp-verify-precondition` with an untracked file listed in the ledger.
- **Expected Evidence:** The precondition gate detects the Git status failure (exit code 1 from `bin/omp-verify-git-integrity`), fails-closed, writes a diagnostic report to stderr, and exits with code 1.
- **Failure Condition:** The precondition gate proceeds to execute tests despite untracked files in the ledger, bypassing the Git integrity check.
- **Initial Failure Expectation:** VALID_INITIAL_FAILURE_POSSIBLE (127)
- **Post-Implementation Success Expectation:** PASS

#### Edge Cases

- **Execution Outside Git Repository:** If executed outside a valid Git directory, the tool must capture the error cleanly, write `Error: Not a git repository` to stderr, and exit with code 2.
- **Empty Ledger:** If the parsed ledger contains zero files in its table, the tool should output `TESTS_RUN=0` and exit with code 0.

---

#### Failure Scenarios

- **Git Command Missing:** If the system path lacks the `git` command, the tool must fail gracefully, log the missing dependency to stderr, and exit with code 2 (VALIDITY_FAILURE).
