## Root Cause Analysis

### Primary Issue 1: M5 Test Hallucination - Python Syntax in Bash Files

**Specific Code Location**: `tests/M5/test_post_approval_workflow.sh` (and all 16 M5 test scripts)

**Evidence**:
```bash
$ head -30 tests/M5/test_post_approval_workflow.sh
#!/bin/bash

# Test Suite: Post-Approval Workflow Orchestration
# Tests: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6
# Total: 30 test cases

set -e

# Test counter

TESTS_PASS=0
TESTS_FAIL=0

# Mock RepairLoopTracker

    def __init__(self, max_cycles=3):  # ← Python method syntax
        self.max_cycles = max_cycles
        self.counter = 0
```

**Root Cause**: The test plan template (`M5S1T1.md`) included Python code snippets for mock objects and routing logic. The `generate-tests` agent erroneously embedded these Python code snippets directly into the bash test scripts instead of using bash functions or converting them to executable bash syntax.

**Gap in Templates**: The `test_template.md` does not specify a strict output format constraint for test scripts. It only documents the framework and setup requirements but does not explicitly state:
1. Test scripts must use the language of their extension (bash scripts = bash syntax)
2. Mock code cannot be embedded directly in production test scripts
3. Test scripts must be syntactically valid before being marked as complete

### Primary Issue 3: Namespace Collision Between AEF Meta-Framework and BariaDAO Project

**Specific Code Location**: Flat `milestones/M{X}/` directory structure

**Evidence**:
```bash
$ find milestones -type f -name "*.md" | sort
milestones/M2/...
milestones/M3/...
milestones/M4/...
milestones/M5/...
milestones/TEMP/...
milestones/archive/...
```

**Affected Milestones**:
- **AEF Meta-Framework M5**: `milestones/M5/M5S1.md`, `milestones/M5/M5S1C.md`, etc. (Post-approval orchestration)
- **BariaDAO Project M5**: Likely `milestones/M5/` exists independently, causing collision

**Root Cause**: The framework does not separate meta-framework milestones from project-specific milestones. Both share the same directory namespace:
- `milestones/M5/` is ambiguous - is this AEF's M5 or BariaDAO's M5?
- No project-scoping mechanism (no `milestones/aef/M5/` vs `milestones/baria/M5/`)
- No prefix or suffix to distinguish meta-framework vs project work

**Impact**:
1. State corruption when two projects both use M5
2. Accidental overwriting of milestone artifacts
3. No clear separation between framework development and project development
4. Ambiguous which milestone definition belongs to which project

**Gap in Framework Design**: The framework architecture assumes a single-project workspace, but the prompt indicates multi-project usage (AEF meta-framework + BariaDAO project). The milestone directory structure needs:
1. Either project-scoped subdirectories (e.g., `milestones/aef/`, `milestones/baria/`)
2. Or unique identifiers (e.g., `milestones/AEF-M5/`, `milestones/BARIA-M5/`)
