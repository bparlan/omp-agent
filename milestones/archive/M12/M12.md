# M12 — AEF DevOps Cycle Foundation

## Status

Proposed

## Objective

Establish a stable, healthy DevOps cycle for the AEF Spec-Driven Development (SDD) pipeline by:

1. Overhauling `manage-development` personas from role-oriented to behavioral-vector-oriented
2. Creating a new `manage-docs` operational governance skill with intake buffer and event-driven docs watching
3. Defining clear handoff contracts between strategic, tactical, and operational layers

This milestone does **not** modify the tactical SDD pipeline behavior beyond persona lens changes. It does **not** refactor existing artifact types beyond adding `operations-consolidation`. It does **not** implement code changes in `core/` beyond artifact registration.

## Motivation

The current AEF skill stack has a clear tactical layer (`manage-development`) and a strategic layer (`manage-roadmap`), but lacks an operational governance layer for `docs/` folder hygiene, hotfix governance, diagram drift, and solution document management.

Additionally, the existing personas in both `manage-development` and `manage-roadmap` are role-oriented placeholders. They lack the cognitive depth needed for realistic team consolidation, pressure-response modeling, and vector-shifting commentary.

Without these foundations:
- Documentation drift goes undetected until it blocks release
- Hotfix reports are not systematically governed
- Diagrams and solutions become orphaned
- Team consolidation outputs are generic rather than insightful
- Handoff boundaries between strategic, tactical, and operational layers are implicit and ambiguous

## Spec Decomposition Plan

- **M12S1** — Behavioral-Vector Persona Overhaul for `manage-development`
- **M12S2** — `manage-docs` Skill Creation: Intake Buffer, Folder Governance, and Event-Driven Watch
- **M12S3** — Handoff Contracts and Cross-Skill DevOps Cycle Integration

## Scope

### In Scope

- **M12S1**: Rewrite `manage-development` personas from role-oriented to behavioral-vector-oriented. Update phase-specific 3-person team assignments. Preserve existing consolidation report format and dual recommendation mechanics. No changes to pipeline orchestration logic.
- **M12S2**: Create new `skills/manage-docs/SKILL.md` with operational governance scope limited to `docs/` folder. Implement `docs/queue/` intake buffer. Define folder governance rules for `docs/hotfixes/`, `docs/diagrams/`, `docs/solutions/`, and official AEF SSD docs. Add event-driven new-file detection for `docs/`. Register `operations-consolidation` artifact type in AEF infra.
- **M12S3**: Document handoff contracts between `manage-roadmap`, `manage-development`, and `manage-docs`. Update `manage-development` with ops handoff points. Define ops cycle trigger points and continuous watch behavior. Validate end-to-end circulation flow.

### Out of Scope

- Refactoring or reorganizing existing `docs/` folder contents
- Modifying tactical SDD pipeline stages or state machine
- Implementing new code in `core/` beyond artifact type registration
- Creating new downstream skills or modifying existing skill behavior beyond the three named skills
- Renaming `manage-roadmap` to `manage-operations`
- Auto-archiving or deleting existing documents during intake classification

## Constraints

- **Sequential Processing**: All three specifications must be executed sequentially. No parallel spec execution.
- **Artifact Naming**: All new artifacts must follow canonical sequential naming: `M12S1`, `M12S2`, `M12S3` for specs; `M12S1C1`, `M12S2C1`, `M12S3C1` for completions; `TC-M12S1-1`, `OPS-C-M12S2-1` for consolidation artifacts.
- **Scope Boundary**: `manage-docs` governs `docs/` only. It must not touch tactical pipeline artifacts, `core/` code, or `milestones/` beyond reading closure artifacts for cross-referencing.
- **Event-Driven Watch**: Auto-scan for new `docs/` files must be opt-in or phase-gated. Initial implementation must include manual trigger capability.
- **Persona Stability**: Once vector personas are defined, their core vectors must not change without explicit user approval. Pressure-shift behaviors may evolve based on usage evidence.
- **No Docs Restructuring**: Existing `docs/` contents must not be moved, renamed, or deleted during intake classification. Only `docs/queue/` files are classified and migrated.

## Assumptions

- The existing `team-consolidation` artifact type registration in `core/artifacts/artifact_types.py` is stable and can be used as a template for `operations-consolidation`
- `milestoner` skill is functional and can generate M12S1-M12S3 specifications from this milestone
- `manage-development` and `manage-roadmap` skill files are writable and plugin copies can be synced
- The `docs/` directory exists at repository root and is writable
- User will review and approve each specification before implementation proceeds

## Notes

- This milestone intentionally avoids modifying existing `docs/` contents. The intake buffer (`docs/queue/`) provides a safe staging area for classification without disrupting existing documentation.
- The behavioral-vector persona model is experimental. Usage evidence from M12 execution will inform whether the vector-shift behavior is correctly calibrated or requires adjustment.
- `manage-docs` is designed as a lightweight operational skill. Its governance scope is intentionally bounded to `docs/` to prevent overlap with `sync-documentation` and `archive-docs`.
- The 3-phase structure is sequential by design. Phase 2 (`manage-docs` creation) does not depend on Phase 1 persona overhaul, but Phase 3 (handoff contracts) depends on both Phase 1 and Phase 2 being stable.
