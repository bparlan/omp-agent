#### Objective

Document explicit handoff contracts between `manage-roadmap`, `manage-development`, and `manage-docs`. Update `manage-development` with ops handoff points and trigger conditions. Define ops cycle trigger points and continuous watch behavior. Validate end-to-end circulation flow with artifact format specifications.

This specification focuses on operational handoff boundaries only. It does not modify tactical pipeline stages or core validation logic.

#### Functional Requirements

##### `FR-HANDOFF_ROADMAP_TO_DEVELOPMENT`
- **Type**: Filesystem State Contract
- **Interface Contract**: `manage-roadmap` produces `ROADMAP.md` and milestone files `milestones/M{X}/M{X}.md`; `manage-development` consumes them to start tactical orchestration.
- **Expected Behavior**: `manage-development` must detect approved milestone artifacts and begin sequential spec generation without manual context handoff.
- **Observable Boundary**: Presence of `milestones/M{X}/M{X}.md` with approval metadata triggers `manage-development` pipeline start.

##### `FR-HANDOFF_DEVELOPMENT_TO_DOCS`
- **Type**: Filesystem State Contract
- **Interface Contract**: `manage-development` produces closure/spec artifacts under `milestones/M{X}/`; `manage-docs` ingests completion reports and operations-consolidation artifacts into `docs/queue/`.
- **Expected Behavior**: `manage-docs` must classify and migrate `docs/queue/` contents to `docs/hotfixes/`, `docs/diagrams/`, `docs/solutions/`, or official `docs/*.md` without modifying existing `docs/` files outside the queue.
- **Observable Boundary**: New files in `docs/queue/` are detectable; migration results in directory moves with preserved filenames.

##### `FR-OPS_HANDOFF_POINTS_IN_MANAGE_DEVELOPMENT`
- **Type**: Structured Schema Contract
- **Interface Contract**: `skills/manage-development/SKILL.md` contains explicit ops handoff points with trigger conditions, artifact formats, and recipient skills.
- **Expected Behavior**: `manage-development` references `manage-docs` and `sync-documentation` at defined phase transitions with exact trigger conditions and required artifact metadata.
- **Observable Boundary**: `skills/manage-development/SKILL.md` includes section markers for ops handoff points, trigger conditions, and artifact schema keys.

##### `FR-EVENT_DRIVEN_WATCH_TRIGGER`
- **Type**: CLI Executable Contract
- **Interface Contract**: `manage-docs` defines a manual trigger for `docs/` new-file detection; auto-scan remains disabled by default.
- **Expected Behavior**: Manual trigger command or documented operational procedure initiates `docs/` scan without background watcher.
- **Observable Boundary**: `skills/manage-docs/SKILL.md` specifies trigger procedure, expected scan output format, and opt-in activation method.

##### `FR-OPERATIONS_CONSOLIDATION_ARTIFACT`
- **Type**: Structured Schema Contract
- **Interface Contract**: `operations-consolidation` artifact type defines required metadata fields and storage rules in `core/artifacts/artifact_types.py`.
- **Expected Behavior**: Consumers (`close-milestone`, `sync-documentation`) can read and validate `operations-consolidation` artifacts using canonical registry APIs.
- **Observable Boundary**: Registry exposes `operations-consolidation` type with schema and storage rule; frontmatter validation passes.

##### `FR-END_TO_END_CIRCULATION_VALIDATION`
- **Type**: Filesystem State Contract
- **Interface Contract**: Execute the DevOps cycle using an existing milestone artifact (M9 or M10) and verify circulation across `manage-roadmap` → `manage-development` → `manage-docs` → `sync-documentation` → `close-milestone`.
- **Expected Behavior**: Artifacts flow through handoff boundaries without missing metadata, invalid paths, or unresolved references.
- **Observable Boundary**: Generated validation report records each handoff boundary check and exits with status `0` when all boundaries pass.

#### Non-Functional Requirements

##### `NFR-SCOPE_BOUNDARY_DOCS_ONLY`
- **Constraint**: `manage-docs` must not modify tactical pipeline artifacts, `core/` code, or `milestones/` beyond reading closure artifacts for cross-referencing.
- **Verification**: Review of touched paths and `code-search` confirmation that only `docs/`, `skills/manage-docs/SKILL.md`, `skills-ledger.json`, and plugin copy are modified.

##### `NFR-SEQUENTIAL_PROCESSING`
- **Constraint**: Specifications must be executed sequentially. No parallel spec execution.
- **Verification**: Implementation artifacts and phase handoff documentation must preserve sequential ordering.
