#### Objective

Define a minimal, standardized `.omp/config.yml` project configuration schema that enables consistent project identification and management across the AEF platform. This specification establishes the contract for project configuration handling in `bootstrap-project` and related skills, integrated with the M9 canonical validation core.

##### Milestone Complexity & Multi-Spec Plan

This milestone is decomposed into 3 sequential specifications to ensure a stable foundation:
1. **M9S1 (Core Infrastructure)**: Establish the Registry, Resolver, and Validator APIs.
2. **M9S2 (Project Configuration)**: [THIS SPEC] Define the project configuration schema and integrate it with the M9 validator.
3. **M9S3 (Healthcenter & Integration)**: Implement the healthcenter skill and integrate affected AEF skills with the artifact system.

#### Functional Requirements

##### `FR-PROJECT_CONFIG_SCHEMA`
*   **Type**: Structured Schema Contract
*   **Interface Contract**: `.omp/config.yml` YAML schema
*   **Expected Behavior**: The system must enforce a schema with three required string fields: `project_id` (UUID or unique string), `project_slug` (kebab-case name), and `version` (semantic versioning).
*   **Observable Boundary**: `validate_metadata(".omp/config.yml", project_config_schema)` returns a success result when fields are present and valid.

##### `FR-PROJECT_CONFIG_VALIDATION`
*   **Type**: Function / API Contract
*   **Interface Contract**: `core/validation.py:validate_project_config(project_root: str)`
*   **Expected Behavior**: Returns a validation result dict containing `valid: bool` and a list of `errors: List[str]`. It must use the canonical `validate_metadata` API.
*   **Observable Boundary**: Successful execution of `validate_project_config()` against a valid `.omp/config.yml` returns `{"valid": true, "errors": []}`.

##### `FR-PROJECT_CONFIG_REGISTRATION`
*   **Type**: Function / API Contract
*   **Interface Contract**: `core/artifacts/registry.py` artifact type "project-config"
*   **Expected Behavior**: Register "project-config" as a canonical artifact type with a defined storage rule pointing to `.omp/config.yml`.
*   **Observable Boundary**: `get_artifact_type("project-config")` returns the registered type definition.

--------------------------------------------------------------------------------

#### Non-Functional Requirements

##### `NFR-MINIMALISM`
*   **Constraint**: The configuration MUST NOT contain mode-aware fields (e.g., "application", "framework") or technology stack declarations.
*   **Verification**: Schema validation MUST fail if unauthorized top-level keys are present in `.omp/config.yml`.

##### Schema Contracts
```yaml
# .omp/config.yml schema
type: object
required:
  - project_id
  - project_slug
  - version
properties:
  project_id:
    type: string
    description: "Unique project identifier"
  project_slug:
    type: string
    pattern: "^[a-z0-9-]+$"
    description: "URL-safe name for the project"
  version:
    type: string
    pattern: "^\\d+\\.\\d+\\.\\d+(-stable)?$"
    description: "Semantic version of the project"
additionalProperties: false
```

#### Acceptance Criteria

*   [ ] `.omp/config.yml` with valid fields passes validation with zero errors. `[FR-PROJECT_CONFIG_SCHEMA]`
*   [ ] `.omp/config.yml` with missing `project_id` or `project_slug` fails validation. `[FR-PROJECT_CONFIG_VALIDATION]`
*   [ ] `.omp/config.yml` containing a `mode` field fails validation (Negative Requirement). `[NFR-MINIMALISM]`
*   [ ] Artifact registry returns the correct storage path `.omp/config.yml` for type `project-config`. `[FR-PROJECT_CONFIG_REGISTRATION]`
