## Objective

Implement the second phase of the Canonical Artifact Identity and Storage Architecture, focusing on defining the canonical directory structure and implementing a dynamic artifact resolution system. This specification establishes the physical storage contract for AEF artifacts and provides a deterministic path resolution mechanism that decouples artifact identity from filename conventions.

### Milestone Complexity & Multi-Spec Plan

M7 is broken into three sequential specifications:

- **M7S1 (SPEC-001)** — Complete. Artifact Identity & Metadata Contract. Established canonical machine identifiers, YAML frontmatter mandate, and `validate_metadata.py`.
- **M7S2 (SPEC-002)** — Current. Artifact Resolution & Canonical Storage. Defines the directory structure contract and implements `resolve_artifact.py` with 3-tier priority resolution.
- **M7S3 (SPEC-003)** — Future. Legacy Compatibility & Transition. Defines legacy classification rules, creates a legacy index/manifest, and establishes the "read legacy, write canonical" transition model.

## Functional Requirements

- **FR-6**: Define the canonical directory structure contract for AEF artifact storage. The base path MUST be `milestones/{M_ID}/` where `{M_ID}` is the milestone identifier (e.g., `M7`). Artifact type subdirectories are OPTIONAL but when present MUST follow the naming convention: `specifications/`, `verifications/`, `tests/`, `investigations/`, `implementations/`, `evaluations/`, `reviews/`, `audits/`. The structure MUST be documented in `docs/ARTIFACT_ARCHITECTURE.md` as a formal contract.

- **FR-7**: Implement `resolve_artifact.py` in `bin/` that resolves an artifact identifier (canonical or legacy) to a resolved file path using the following strict 3-tier priority:
  1. **Explicit YAML metadata** — Scan YAML frontmatter of files in the milestone directory. If a file's `id` field matches the queried identifier, return that file path.
  2. **Canonical Directory Context** — If the identifier implies a type (e.g., `SPEC-002` implies `specifications/`), search within the corresponding type subdirectory in `milestones/{M_ID}/`.
  3. **Filename heuristics (Legacy only)** — Match against legacy filename patterns (e.g., `M{X}S{Y}.md`, `M{X}S{Y}V.md`, `M{X}S{Y}T{Z}.md`, `M{X}S{Y}I{Z}.md`). This tier MUST only resolve pre-M10 artifacts.

- **FR-8**: Implement conflict detection in `resolve_artifact.py` that detects when a file's YAML `type` field disagrees with its directory location. For example, a file at `milestones/M7/specifications/` with `type: verification` in its frontmatter MUST be flagged as a conflict. The conflict report MUST include the file path, expected type (from directory), actual type (from YAML), and the queried identifier.

- **FR-9**: `resolve_artifact.py` MUST support querying by both canonical IDs (e.g., `SPEC-001`, `VER-002`) and legacy IDs (e.g., `M7S1`, `M7S1V`). The resolution method used (which tier produced the match) MUST be reported in the output.

- **FR-10**: Update `docs/ARTIFACT_ARCHITECTURE.md` to formalize the canonical directory structure as a contract, replacing the current "Proposed" section language with definitive specification language. The document MUST reference FR-6 through FR-9 and describe the 3-tier resolution priority.

## Data Flow

1. User or agent invokes `resolve_artifact.py` with an identifier and milestone ID.
2. Tier 1: Script scans the milestone directory tree for files with YAML frontmatter. If a file's `id` field matches the queried identifier, it is returned immediately.
3. Tier 2: If no YAML match, the script infers artifact type from the identifier prefix (e.g., `SPEC-` → `specifications/`, `VER-` → `verifications/`). It searches within the corresponding type subdirectory of `milestones/{M_ID}/`.
4. Tier 3 (legacy fallback): If still not found, the script applies legacy filename heuristics to match against pre-M10 naming patterns.
5. Conflict detection: If a file is found in Tier 2 or Tier 3, the script checks that the file's YAML `type` field (if present) is consistent with its directory location. Inconsistencies are reported.
6. The resolved path is printed to stdout. If verbose mode is enabled, the resolution trace is printed to stderr.

## Assumptions

- The Python environment has `PyYAML` installed (same dependency as `validate_metadata.py`).
