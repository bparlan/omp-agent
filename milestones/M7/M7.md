# M7: Canonical Artifact Identity

**Goal**: Implement the Canonical Artifact Identity and Storage Architecture, transitioning AEF from fragile filename heuristics to a stable, metadata-driven identity and resolution model with full legacy compatibility.

**Motivation**: Currently, AEF treats human-readable filenames as lifecycle semantics (e.g., misinterpreting `M5S1I1-CORRECTED`). This causes agents to misclassify documents, hallucinate lineage, and fail during test generation. We must decouple artifact identity, artifact type, lineage, and lifecycle state into machine-readable YAML frontmatter, supported by a deterministic directory resolution fallback, without destroying M1-M9 legacy artifacts.

**Scope**:
*   **Spec 1: Artifact Identity & Metadata Contract**: Define canonical machine identifiers (SPEC-001, VER-001, TEST-001, INV-001). Mandate YAML frontmatter for all artifacts containing: `id`, `type`, `title`, `milestone_id`, `status`, and `derived_from` (lineage). Prohibit semantic qualifiers in IDs. Write a validation script (`validate_metadata.py`).
*   **Spec 2: Artifact Resolution & Canonical Storage**: Define the canonical directory structure (e.g., `milestones/{project_slug}/{M_ID}/`). Implement a dynamic path resolution script (`resolve_artifact.py`) that strictly follows this priority: 1. Explicit YAML metadata -> 2. Canonical Directory Context -> 3. Filename heuristics (Legacy only). Implement conflict detection if a file's YAML type disagrees with its directory location.
*   **Spec 3: Legacy Compatibility & Transition**: Define the legacy classification rules for pre-M10 artifacts. Create a legacy index/manifest mechanism to track M1-M9 files. Ensure the transition model is "read legacy, write canonical"—no destructive bulk migrations, no automatic overwriting of historical Markdown files.

**Out of Scope**:
*   Direct overwriting or renaming of M1-M9 legacy artifacts.
*   Generation of placeholder tests, outlines, or pseudo-code.
*   Non-bash test scripts (e.g., `.py` `pytest` files for markdown/metadata validation).
*   Tests that scan their own source code.
*   Requirements based on exact text matching.

**Success Criteria**:
*   All requirements must be assigned stable IDs (`FR-1`, `NFR-1`).
*   No requirement may be defined as "The document must contain the phrase [X]". Requirements must define observable script executions, YAML schemas, or file existence.
*   `validate_metadata.py` correctly parses valid YAML frontmatter and rejects invalid schemas.
*   `resolve_artifact.py` correctly routes dummy files based on the 3-tier priority sequence.

**Risks**:
*   Potential for agents misclassifying documents due to incomplete or incorrect metadata.
*   Difficulty in ensuring full legacy compatibility without introducing new bugs.
*   Complexity of the resolution logic leading to incorrect artifact retrieval.

**Notes**: This milestone is complex and will be broken into three sequential specifications (S1, S2, S3).
