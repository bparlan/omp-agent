# Test Generation & Specification Quality Improvement Initiative

## Executive Summary

This document outlines targeted improvements to increase the quality of artifacts generated by `milestoner`, `generate-spec`, and `generate-verification` skills. The focus is on eliminating redundancy, improving requirement traceability, and ensuring comprehensive test coverage through higher-quality specification development.

## Core Quality Issues Identified

### Current State Problems
1. **Repetitive boilerplate in generated tests** - 70%+ redundancy across test files
2. **Insufficient behavioral validation** - Tests verify existence, not functionality
3. **Weak requirement traceability** - Tests don't map to meaningful specification requirements
4. **Limited test scope** - Smoke tests instead of comprehensive coverage
5. **Inconsistent artifact quality** - Varying standards across generated outputs

## Targeted Skill Improvements

### 1. `milestoner` Enhancement Prompts

#### A. Requirement Structure Validation
```
When creating new milestones, validate that:
- Each milestone has exactly 4 sequential specifications (M9S1, M9S2, M9S3, M9S4)
- Each specification has clear ownership boundaries
- Scope definitions explicitly exclude later spec concerns
- Spec layering rules are enforced (M9S1 ≠ M9S2 ownership)

Failure Response: "Milestone M{X} violates spec layering rules. M9S1 must own core infrastructure; M9S2+ cannot redefine as CLI executable contracts."
```

#### B. Artifact Contract Enforcement
```
For artifact-creating skills, enforce:
- Canonical artifact identity assignment before creation
- Required metadata generation with validation
- Canonical storage location placement
- Pre-creation artifact validation completion
- Created artifact identity reporting

Validation Rules:
- Missing artifact identity: "ERROR: Artifact creation incomplete. No canonical identity assigned. Cannot proceed."
- Incomplete metadata: "ERROR: Artifact validation failed. Missing required metadata. Artifact not approved for creation."
- Wrong storage location: "ERROR: Storage violation. Artifact not placed in canonical location. Move to {expected_path}."
- Validation failure: "ERROR: Pre-creation validation failed. Artifact cannot be created. Fix issues then retry."
```

### 2. `generate-spec` Enhancement Prompts

#### A. Concrete Interface Contract Extraction
```
When processing milestone M{X}:
1. Parse M{X}.md to extract ALL observable boundaries
2. Convert requirements to mechanical contracts:
   - "Generate CLI tool for artifact validation" → "Create src/omp_cli/validate_metadata.py with validate_file(identity, type) exit codes"
   - "Support artifact registry operations" → "Create src/core/artifacts/registry.py with register_type(), get_type() methods"
   - "Implement artifact resolution" → "Create src/core/artifacts/resolve.py with resolve_artifact(identity, type, strict) function"

Validation:
- If spec contains prose without concrete boundaries: "ERROR: Specification M{X}S{Y} incomplete. Missing mechanical contracts. Provide concrete CLI/file/interface definitions."
- If spec has unresolved placeholders: "ERROR: Placeholder detected in M{X}S{Y}. All ? values must be replaced with concrete values."
- If spec missing traceability: "ERROR: Requirement traceability broken. SPEC-M{X}S{Y} missing derived_from links to prerequisite specs."
```

#### B. Specification Completeness Validation
```
Before completing specification M{X}S{Y}:
1. Verify all required frontmatter fields exist with concrete values
2. Check test_set file exists and references only legitimate tests
3. Validate derived_from chains are complete and correct
4. Ensure spec clearly defines what is NOT in scope for later specs

Required Frontmatter Fields:
- id: "SPEC-M{X}S{Y}" (format: SPEC-{milestone}{spec})
- type: "specification"
- title: "Concrete title describing M{X}S{Y} scope"
- milestone_id: "M{X}"
- derived_from: ["SPEC-M{X}S{Y-1}"] (never include self-references)
- status: "draft"
- Any additional required fields with concrete values (never "?")

Error Responses:
- Missing field: "ERROR: Specification M{X}S{Y} incomplete. Missing required field: {field_name}."
- Invalid value: "ERROR: Invalid frontmatter value in M{X}S{Y}. Field {field_name} must be concrete value, not placeholder."
```

### 3. `generate-verification` Enhancement Prompts

#### A. Requirement-to-Test Mapping Validation
```
When generating verification protocol VER-M{X}S{Y}V:
1. For EACH requirement in M{X}S{Y}:
   - FR-{N}: "Verify {requirement_description}"
   - Generate at least ONE implementation test that validates the requirement
   - Test must fail on blank codebase (Exit Code 127) or pass with proper implementation

Test Generation Rules:
- If requirement describes CLI tool creation: Generate IMPLEMENTATION_CHECK testing binary existence and functionality
- If requirement describes API contract: Generate IMPLEMENTATION_CHECK testing interface compliance
- If requirement describes schema: Generate SPECIFICATION_CHECK testing schema validation
- If requirement describes configuration: Generate ENVIRONMENT_CHECK testing setup

Error Response:
- Missing test for requirement: "ERROR: Verification incomplete. Requirement FR-{N} has no corresponding test. Cannot proceed."
- Test performs prose-grep: "ERROR: TDD leak detected in VER-M{X}S{Y}V. Test for FR-{N} performs document grep instead of functionality validation."
```

#### B. Test Strategy Classification Enforcement
```
Classify each verification test as:
- IMPLEMENTATION_CHECK: Tests CLI tools, APIs, core logic (FAIL on blank codebase)
- SPECIFICATION_CHECK: Tests schemas, docs, configuration (PASS immediately)
- ENVIRONMENT_CHECK: Tests system dependencies, setup (PASS immediately)

Classification Rules:
- If test checks if file exists: IMPLEMENTATION_CHECK
- If test checks if module imports: IMPLEMENTATION_CHECK
- If test validates schema: SPECIFICATION_CHECK
- If test checks if directory exists: ENVIRONMENT_CHECK

Error Response:
- IMPLEMENTATION_CHECK without target: "ERROR: Invalid test classification in VER-M{X}S{Y}V. IMPLEMENTATION_CHECK requires target binary/API. Reclassify or add target."
- SPECIFICATION_CHECK that performs implementation: "ERROR: Incorrect classification in VER-M{X}S{Y}V. SPECIFICATION_CHECK must validate schema/docs, not execute code."
```

### 4. Cross-Skill Quality Gate Prompts

#### A. Pre-Implementation Validation
```
Before any implementation:
1. Check M{X}TE.md status
2. Verify TESTS_RUN + TESTS_FAILED = total tests
3. Confirm VALID_INITIAL_FAILURES = expected failures
4. Ensure INVALID_TESTS = 0
5. Verify TDD_LEAKS = 0

Validation Rules:
- If any INVALID_TESTS > 0: "QUALITY GATE FAILED: M{X}TE.md shows invalid tests. Must repair before implementation."
- If any TDD_LEAKS > 0: "QUALITY GATE FAILED: M{X}TE.md shows TDD leaks. Must fix verification protocol before implementation."
- If EXIT_CODE != 0: "QUALITY GATE FAILED: M{X}TE.md shows blocked state. Repair artifacts and retry."
```

#### B. Artifact Consistency Validation
```
Validate consistency across all M{X} artifacts:
1. All .md files: Same frontmatter structure, no "?" values
2. All test files: Consistent shebang, no NUL bytes, meaningful exit codes
3. All specifications: Complete traceability, no circular references
4. All verification: Strict test classification, proper requirement mapping

Consistency Rules:
- If file has different frontmatter: "INCONSISTENCY: M{X}S{Y}.md frontmatter differs from standard. Must normalize."
- If test file missing shebang: "INCONSISTENCY: tests/M{X}/S{Y}/test_*.sh missing shebang. Must add #!/bin/bash."
- If spec has circular reference: "INCONSISTENCY: Circular dependency detected in derived_from. Break dependency before proceeding."
```
